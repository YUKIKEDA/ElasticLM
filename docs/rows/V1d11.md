# V1d11（Issue #329）: SaaS 型のリースの検証の、失効した鍵と証明書の期間の検査にテストを足す

V1d の指摘 R8-1。SaaS 型のリースの検証（`LeaseVerifier.VerifyHosted`）の、無効にした鍵と証明書の期間の検査にテストを足す。確かめる文は、設計 §20.2 の「無効にした鍵 ID の証明書とトークンが拒否されること、期限の切れた古い証明書がファイルにあっても正しい証明書で検証できること、`iat` が証明書の期間外のトークンが拒否されること」と、§5.3 の T12 である。製品のコードは変えない。

## Grill の記録

## 退けた案

- **決定:** Issue が挙げた場合（無効にした署名鍵、証明書の `exp` と `nbf` の境の ±300・±301 秒、別のインストール鍵、未来の `iat` の境、期限の境）に、設計 §20.2 の文が言う残りを足す。無効にしたルート、関係のない無効の鍵 ID、期限の切れた証明書と正しい証明書の並び（両方の順）、時計の守りが断る場合、順序（無効にした署名鍵で、使える証明書がない場合に `ELM_KEY_REVOKED`）である。製品のコードは変えない（持ち主の決定、問 11-1 の推奨案 A。2026-11-13。設計 §20.2）。
- **理由:** §20.2 の文は、無効にした鍵 ID の証明書とトークンを拒むこと、期限の切れた古い証明書がファイルにあっても正しい証明書で検証できること、`iat` が証明書の期間外のトークンを拒むことを言う。Issue の場合だけでは、ルートの無効、古い証明書の並び、無効の一覧が関係のない ID を巻き込まないことが、SaaS 型の経路でテストのないまま残る。無効の鍵の検査を外しても、署名鍵の証明書が断られて `ELM_UNTRUSTED_KEY` になるので、コードを確かめる。手順 2 が手順 3 より先であることは、両方に外れる入力で確かめる。
- **却下した案:** (B) Issue の場合だけにテストを足す（上の残りが、SaaS 型の経路でテストのないまま残る）。
