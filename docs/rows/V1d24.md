# V1d24（Issue #343）: クライアントとファイルの置き方の、V1d の低の指摘を片付ける

## Grill の記録

Issue #343 のコメント「V1d24 の Grill」に、持ち主の答え（2026-11-14、問 24-1〜24-7 のすべてが推奨案 A）がある。設計の本文（`../design.ja.md`）は、§10.2（Linux と macOS の所有者、誰が通るか）、0.53、§5.3 の T20、§5.4 の `admin.sock` の行、§12.6.2（一時ファイルの作り方）、§12.7.4、§13.5（ピンと、同じ写しを足さないこと）、§13.7（走らせる利用者、`EnsureWritable`、`--license` の書き方）と、§20.7 と §22 の V1d24a の行を持つ。

### 測った事実（`origin/main` の c408111。Grill の事実調べ）

- F29: 名前の決まった一時ファイルを `CreateNew` なしで書いていた。`ActivationStore.Write` と `LicenseFiles.Write` は `File.WriteAllBytes`、`LicenseClient.SaveBorrow` は `FileMode.Create`、`ElmServer.EnsureWritable` は `File.WriteAllBytes` で書いて消していた。`AdminLoginFile.Write` は、置き換えに失敗したとき一時ファイルを消さなかった。Linux の root で、ほかの利用者がそのパスに置いたシンボリックリンクをたどって `/root` の下のファイルを書き換えること、`EnsureWritable` がリンクの先を空にすることを走らせた。Windows で、先に置かれた一時ファイルのアクセス規則が、書いたファイルに残ることを走らせた。同じ種類: `ServerPins.TryWrite`（乱数の名前を `File.WriteAllBytes` で書く）。`FileClockGuard`（`ElasticLM.Licensing`）は Issue #444 にした（問 24-3）。
- F33: `ProtectedFiles.CheckUnix` はモードだけを見ていた（Windows の `CheckWindows` はフォルダーと親の所有者を見る）。Linux の root で、`nobody` が持つモード 0700 のフォルダーが通り、`installation.key` と `admin.token` がそこに書かれ、`nobody` がファイルを置き換え、`admin.sock` の場所にソケットを作れることを走らせた（T20。トークンが `nobody` に漏れることは推し量りで、走らせていない）。.NET 10 には Unix のファイルの所有者を読む API がない。
- F48: `LicenseClient` が持つサーバーライセンスの写しは、答えにヘッダー `ELM-Server-License` がないか、知らない `jti` を名指すたびに、同じ `jti` の写しを足し（`AddIdentity`）、上限 8 で捨てる写しを、リースが指す `jti` で探すので、同じ `jti` の写しはどれも捨てられず、8 件を超えて増えた。借り出しのための写しのファイル（`_identityFiles`）は、捨てるときも消さなかった。
- R8-D5: F33 の文書の側。`explanation/devices-and-proofs.md` は、前から「OS を問わず、ほかの利用者が持つフォルダーを使わない」と書いていて、Linux と macOS のコードと違っていた。

### 持ち主が決めたこと（2026-11-14、すべて推奨案 A）

- 問 24-1、24-2（F29）: コードで直す。名前は今のまま、先に消してから `CreateNew`（Unix は 0600）で作り、置き換えに失敗したら消す（`AdminToken.CreateAsync` と同じ形）。範囲は `ActivationStore`、`SaveBorrow`、`LicenseFiles`、`ElmServer.EnsureWritable`、`AdminLoginFile.Write` の失敗のあとの削除。§12.6.2、§12.7.4、§13.7 の文を直す。
- 問 24-3: `ServerPins.TryWrite` もこの行で直す。`FileClockGuard` は別の Issue（#444）。
- 問 24-4（F33）: 設計 §10.2、0.53、T20 とコードを変え、Unix でもフォルダーと親の所有者を確かめる（libc の `geteuid` と、Linux の `statx`、macOS の `stat` を `LibraryImport` で呼ぶ）。
- 問 24-5: 所有者は今の利用者（実効ユーザー ID）か root。モードの確かめも残す。`elm server` の、インストール鍵を読むコマンドは、サービスの利用者で走らせる（`elm-cli.md` を直す）。
- 問 24-6: Linux と macOS の CI で `sudo` を使い、落ちるテストを先に書く（持ち主が `nobody` のフォルダー、親が `nobody` のフォルダー）。
- 問 24-7（F48）: `AddIdentity` で `TokenId` の同じ写しを足さない（手元の写しを今の写しにし、新しい写しは捨てる）。上限で捨てるときは `_identityFiles` の項目も消す。ヘッダーのない答えを 9 回以上返して 8 件を超えないことを、落ちるテストで先に確かめる。

### こちらが決めたこと

- 一時ファイルの作り方を 1 か所にした: `FileReplacement.CreateNew`（先に消し、`CreateNew` で作り、Unix は 0600、書けなければ作ったファイルを消す）と `FileReplacement.Write`（`CreateNew` のあと `Move`、置き換えに失敗したら一時ファイルを消す）。`ActivationStore`、`LicenseFiles`、`ServerPins` は `Write` を、`SaveBorrow` と `EnsureWritable` は `CreateNew` を使う。`SaveBorrow` は、置き換えのやり直し（§12.6.2 の「使わないファイル」）を使わないままにするため、`File.Move` を直接呼び、失敗したら一時ファイルを消す。`AdminToken` と `ServerPins` の、同じ働きの私的な削除の関数は、`FileReplacement.DeleteQuietly` にまとめた。
- libc の名前: Linux は `libc.so.6`。NativeAOT の実行ファイルは `LibraryImport` の名前を実行のときに探し、`libc` の名前を `libc.so.6` に読み替えない（dotnet/runtime release/10.0 の `NativeLibrary.NativeAot.cs` と `LibraryNameVariation.Unix.cs`。`libc` は `libc.so` になり、glibc の端末では、ないか、リンカーのスクリプトである）。musl の動的リンカーは、`libc.so.6` の `dlopen` に musl 自身を返す（musl の `ldso/dynlink.c` の `load_library` の、予約した名前 `c.pthread.rt.m.dl.util.xnet.`）。macOS は `/usr/lib/libSystem.B.dylib`（`MachineIdSources` の IOKit と同じく、フルパス）。
- 確かめの順: 所有者を、モードより先に見る。ほかの利用者のフォルダーは、モードによらず所有者の文で断る。
- F48 のテストのために、`LicenseClient` に内部のプロパティ `ServerLicenseCopies`（写しの数とファイルの数、ロックの中で読む）を足した。外から見える振る舞いでは数が分からないためである。
- テストの中継（`Recorder`）に、答えから `ELM-Server-License` を取り除く `DropServerLicense` を足した。

## 退けた案

- **決定:** Unix の所有者を libc の `geteuid` と `statx`／`stat` で読む（問 24-4）。
- **理由:** .NET 10 に API がない。`statx` は、リリースの下限の glibc 2.28 と、`linux-musl-x64` を作る Alpine 3.24 の musl 1.2.5 にある。
- **却下した案:** `System.Native` の内部の `SystemNative_Stat` を呼ぶ（公開の契約でなく、構造体の形が版で変わりうる）。ファイルを作ってその所有者と比べる（フォルダーそのものの所有者は分からない）。頁の文だけを直す（F33 の置き換えと `admin.sock` の待ち受けが残る）。

- **決定:** 名前の決まった一時ファイルは、名前を変えずに、先に消してから `CreateNew` で作る（問 24-1）。
- **理由:** 置かれたリンクやファイルを開かずに消し、消したあとに置かれたものは `CreateNew` が断る。名前を変えないので、残った一時ファイルは次の書き込みが消す。
- **却下した案:** 乱数の名前にする（残った一時ファイルを誰も消さなくなる）。今のまま `§5.4` に書く（フォルダーに書ける者の範囲を、F33 の直しのあとも、このファイルだけ広く残すことになる）。
