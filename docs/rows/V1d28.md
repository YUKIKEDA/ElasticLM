## 退けた案

- **決定:** Dependabot のセキュリティの更新も有効にし、`cooldown` が効かないことを例外として書く（問 1）。
- **理由:** NuGet の版の更新は、開いている PR が上限に達すると止まる。セキュリティの更新は別の上限を持つので、そのあいだも直した版の PR が出る。`cooldown` と週 1 回の間隔も待たない。直した版は勧告が名指しし、PR はレビューと CI を通る。
- **却下した案:** 警告だけを有効にし、直しは人が行の作業で行う（すべての更新に `cooldown` が効くが、警告を見て動くのが人の記憶に頼る）。

- **決定:** SHA で固定した actions に警告が出ないことを、§5.4 に受け入れる（問 2）。
- **理由:** 警告は semver の参照にだけ出る。代わりに、週 1 回の版の更新が新しい版を運び、`pins` のジョブがタグとの一致を確かめる。
- **却下した案:** 版のコメントから勧告を引く検査を、この行で CI に足す（外の API に頼り、この行の範囲を越える。候補として `../design-decisions.md` に残した）。SHA の固定をやめてタグに戻す（V1d22 の決定に反し、タグの付け替えによる乗っ取り（T25）を止められなくなる）。

- **決定:** 有効にしたあとで、出た警告と依存グラフを読み、§5.4 と `dependencies.mdc` を事実に合わせる（問 3）。
- **理由:** 2026-11-27 の依存グラフは、pnpm の lock から npm の版を読んでおり、「pnpm 12 の lock では警告が出ない」という今の文と食い違うかもしれない。NuGet の版は `>= 0` で、警告が版で絞れるかは、有効にするまで分からない。
- **却下した案:** 今の文のままにする（事実と違うかもしれない文が残る）。

- **決定:** ルートの `nuget.config` は、`<clear/>`、`nuget.org` だけ、`*` を `nuget.org` に割り当てる（問 4）。
- **理由:** 端末とユーザーの取得元を消し、割り当ても書くので、あとで取得元を足したときにも、どのパッケージをどこから取るかが抜けない。キーがサンプルと同じなので、サンプルの割り当ては変わらない。
- **却下した案:** `<clear/>` と `nuget.org` だけで、割り当てを書かない（取得元が 1 つのうちは同じだが、取得元を足したときの抜けを防げない）。パッケージの接頭辞ごとに割り当てる（取得元が 1 つなので益がなく、依存を足すたびに手入れが要る）。

- **決定:** F23 は、5 か所を直すだけにする（問 5）。
- **理由:** 行は低の指摘の片付けで、規則（`security.mdc`）とレビューが守る。
- **却下した案:** `tools/ElasticLM.ActionPins` に、`run:` の値の `${{` を断る検査を足す（道具の読み方の規則を `run` にも決め直すことになる。候補として `../design-decisions.md` に残した）。

- **決定:** CodeQL の 2 件は、理由を書いて「won't fix」で閉じる（問 6）。
- **理由:** 重なった範囲が当たる文字は変わらず、スクリプトは配布物に入らない。スキルは `skills-lock.json` の `computedHash` で固定している。
- **却下した案:** 手元の写しを直す（`computedHash` とずれ、スキルを更新するたびに直し直す）。開けたままにする（CodeQL の 0 件という基準が崩れたままになる）。

- **決定:** 木にない 7 つのワークフローは、消さず、無効にもせずに残す（問 7）。
- **理由:** ファイルを持つブランチがないので動かない。その実行は、設計と規則と行の記録が根拠として名指ししている。
- **却下した案:** `gh workflow disable` で止める（実行は残るが、同じパスの一時のワークフローを、あとで作っても動かなくなる）。実行を消して一覧から外す（根拠が消える）。
