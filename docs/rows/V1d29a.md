# V1d29a（Issue #472）: `elm-server` を Windows のサービスとして動かせるようにする

## Grill の記録

- ソース（dotnet/runtime の release/10.0）:

  - `ServiceBase` は、停止のあいだの `waitHint` を 0 で報告し、受ける停止の合図は STOP と SHUTDOWN だけで、preshutdown を受けない。
  - `WindowsEventLog.WriteEntry` は、ソースを登録できない（`SecurityException`）と、そのプロセスの書き込みを止め、ソース `Application` で「Unable to log .NET application events.」を書こうとする。

  - Slim ビルダー（dotnet/aspnetcore の release/10.0、`WebApplicationBuilder.AddDefaultServicesSlim`）は `AddSimpleConsole` だけを足し、既定のビルダーの「イベントログは `Warning` 以上」（`HostingHostBuilderExtensions.AddDefaultServices`）の規則を持たない。

- `ProtectedFiles.CheckWindows` が許すのは、Administrators、SYSTEM、`WindowsIdentity.GetCurrent().User` の 3 者で、許可の規則がほかの者を名指せば断る。インストール鍵と管理者トークンは、DPAPI の端末の範囲（`CRYPTPROTECT_LOCAL_MACHINE`、`Dpapi.cs`）で守る。
- 確かめていないこと: サービスとしての実際の起動と停止（Grill の調べのシェルは管理者でなかった。実装の E2E が CI で確かめる）、Linux と macOS の発行での増え方（CI で測る）、OS の停止、SCM がサービスに与える今のディレクトリ、手順 1〜8 で止まる起動に再起動の設定が効くか。

### 持ち主が決めたこと（2026-11-28、すべて推奨案）

- 問 1: `Microsoft.Extensions.Hosting.WindowsServices` 10.0.14 を足し、`AddWindowsService` を Windows のときだけ呼ぶ。§21 に行を足す。Linux と macOS の増え方は CI の NativeAOT のジョブで測ってから書く。
- 問 2: `server.stopped` を書き、利用ログと借り出しの記録を閉じる処理を、自前のホストのサービスに移し、SCM に STOPPED を報告する前に済ませる。§13.1 の R11 の文を書き直す。
- 問 3: `ShutdownTimeout` は既定の 30 秒のまま。OS の停止のときは 5 秒で強制終了されうること、次の起動がそれを強制終了として数えることを §13.4 に書く。停止にかかる時間は E2E で測る。
- 問 4: サービスのときの運用のログはイベントログ（Application、ソース `elm-server`）、既定の段は `Warning` 以上。
- 問 5: `HostRequestLog.ProviderOf` に `EventLog` の別名を足し、V1d4a と同じ形のテストを足す。
- 問 6: サービスとして動くときは、起動の誤り（終了コード 1 と 2、拇印とマシン指紋の行）の `error:` の 1 行を、決まったイベント ID の `Error` でイベントログにも書く。
- 問 7: 支えるアカウントは LocalSystem（と通常のユーザーアカウント）。§10.2 の確かめは変えない。
- 問 8: 最初の順は、登録、1 度起動してサービスにフォルダーとインストール鍵を作らせる、昇格したターミナルで `elm server activate`、起動。設計と文書に書く。
- 問 9: 動きは変えず、サービスでは `--config` と設定のパスを絶対のパスで書くと案内する。
- 問 10: `New-Service` で登録し、`sc.exe failure elm-server reset= 86400 actions= restart/60000/restart/60000/restart/60000` で再起動を設定する。`failureflag` は既定。サービスの名前は `elm-server`。
- 問 11: Windows の CI の E2E で、一意の名前で登録、起動、`sc stop`、STOPPED、`server.stopped`、イベントログの起動の誤りの行を確かめ、サービスを消す。
- 問 12: 設計（§13.1、§13.4、§18.3、§21、§10.2）と Reference の頁（`logs.md`、`server-configuration.md`、英語と日本語）を直す。how-to は V1d30。

### こちらが決めたこと

- 問 2 の「`IHostedService` の `StopAsync`」は、`IHostedLifecycleService` の `StoppedAsync` にした。ホストは `StopAsync` を登録の逆順で呼び、Kestrel を止める `GenericWebHostService` との順が登録の順で決まる。`StoppedAsync` は、どのホストのサービスの `StopAsync` よりもあとで、`ApplicationStopped` の前に呼ばれる（`Host.StopAsync`）。Kestrel が止まってから、STOPPED の報告の前に閉じるという問 2 の意味は変わらない。
- 起動の誤りのイベント ID は 50 にした。`ServerLog` の ID（1〜42）と重ならない。

### 実装

- `ServerService`（`src/ElasticLM.Server/ServerService.cs`）: `AddTo` は Windows のときだけ `AddWindowsService`（サービスの名前 `elm-server`）と `KeepEventLogAtWarning` を呼ぶ。`KeepEventLogAtWarning` は、構成のあと（`PostConfigure`）に、イベントログの提供者の、分類を問わない `Warning` の規則を、規則の一覧の先頭に入れる。提供者を問わない設定には負けず（`LoggerRuleSelector` は提供者の規則を取る）、イベントログの提供者の設定（別名 `EventLog` と完全な名前のどちらでも）は、あとに来るので、名指した分類だけを変える。`ElmServer.Build` は、`HostRequestLog.Raise` より前にこれを呼ぶので、`Raise` はこの規則を見て、イベントログの提供者の規則も足す。`ReportStartError` は、`WindowsServiceHelpers.IsWindowsService()` のときだけ、`EventLog.WriteEntry("elm-server", <行>, Error, 50)` で書き、`SecurityException`、`UnauthorizedAccessException`、`InvalidOperationException`、`Win32Exception`、`ArgumentException`、`IOException` は何もせずに捨てる。`Program.cs` は、`error:` の行を書くすべての所（使い方の誤り、設定の誤り、起動の誤り）で、標準エラーとこのメソッドの両方に書く。
- `ServerStop`（`src/ElasticLM.Server/ServerStop.cs`）: `IHostedLifecycleService` で、`StoppedAsync` だけが `ElmServer.CloseAsync` を呼ぶ。`ElmServer.StartAsync` は、`Build` に渡して登録し、サーバーを作ったあと、`app.StartAsync` の前に `Close` を設定する。`CloseAsync` は、前の `StopAsync` がしていたこと（サーバーライセンスの更新を止める、3 つのタイマーを止める、`_reloadLock` の中で `server.stopped` を書いて記録を閉じる、最後にロックを放す）を 1 度だけする。`StopAsync` は、`CloseAsync` が済んでいれば何もせず、そうでなければホストを止めてから `CloseAsync` を呼ぶ。ホストを止めるところで例外が出たときは、前と同じくロックを放してから投げ直す。
- `HostRequestLog.ProviderOf` は、`EventLog` を `EventLogLoggerProvider` の完全な名前に直す（`internal` にして、`ServerService` も使う）。

### V1d30 の how-to への申し送り

- 再起動の設定（`sc.exe failure … actions= restart/60000/restart/60000/restart/60000`）が、サーバーライセンスのない最初の起動（SCM につながる前に終了コード 1 で終わる）に効くなら、SCM はその起動を 60 秒おきに最大 3 回やり直す。効くかどうかは、この行では確かめていない（§13.1 の「登録」）。how-to は、再起動の設定を、最初の起動とサーバーライセンスの有効化のあとに置くか、効いても困らないことを書く。
- 通常のユーザーアカウントで動かすときに、管理者がソース `elm-server` を先に登録する手順を書く。候補は、昇格した PowerShell 7 での `[System.Diagnostics.EventLog]::CreateEventSource('elm-server', 'Application')` と、`New-EventLog -LogName Application -Source elm-server`（この機械の PowerShell 7.7.0 では `Get-Command` が `Microsoft.PowerShell.Management` のものとして見つけた）で、どちらもこの行では試していない（ページの再レビューの指摘）。
- 通常のユーザーアカウントで動かすときの 3 つの条件（「サービスとしてログオン」の権利、ソース `elm-server` を管理者が先に登録すること、サーバーライセンスのコマンドをそのアカウントで実行すること。§10.2）は、この行の CI で確かめていない。
