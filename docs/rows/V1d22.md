# V1d22（Issue #341）: `ci.yml` の actions を、コミットの SHA で固定する

## Grill の記録

Issue #341 のコメント「V1d22 の Grill」に記録した。問 22-1〜問 22-6。持ち主の決定はどれも推奨案 A（2026-11-14）。その前のコメントで、持ち主は `ci.yml` の `actions/checkout` に `persist-credentials: false` を付けることを、この行の点に足した（V1d10a の Grill の行の外）。決めた形は設計（`../design.ja.md`）§20.5 の「アクションの固定の確かめ」、脅威は §5.3 の T25、SPA のジョブの文は §15.2 にある。

- 調べた事実（Grill は `origin/main` の c408111。実装の前に abe8290 で見直した）:
  - `ci.yml` の `uses:` は 11 行で、SHA で固定していたのは 4 行（`actions/setup-node`、`actions/upload-artifact`、`actions/download-artifact` の 2 行）だった。タグのままだったのは、`actions/checkout@v7`（3 行）、`actions/setup-dotnet@v6`（2 行）、`actions/cache@v6`（2 行）。abe8290 で足された V1d10a の段は `uses:` を増やしていない。
  - `release.yml` と `measure.yml` の `uses:` は、どれも SHA と版のコメントを持ち、どの SHA もコメントの版のタグのコミットと同じだった。
  - 2026-11-14 の `git ls-remote` で、`actions/checkout` の `v7` と `v7.0.1` は 3d3c42e5aac5ba805825da76410c181273ba90b1、`actions/setup-dotnet` の `v6.0.0` は a98b56852c35b8e3190ac28c8c2271da59106c68（`release.yml` と `measure.yml` が使う版）、`actions/cache` の `v6` と `v6.1.0` は 55cc8345863c7cc4c66a329aec7e433d2d1c52a9 だった。
  - 使う composite のアクションは `actions/upload-pages-artifact`（`release.yml` の `site`）だけで、中で `actions/upload-artifact` を SHA と版のコメントで呼ぶ。
  - `ci.yml` の 3 つの `actions/checkout` は `persist-credentials: false` を持たなかった。`ci.yml` とそこで動くものは、git の資格情報を使わない。
  - `repos/<r>/commits/<sha>` の API は、フォークにだけあるコミットも、親のリポジトリの名前で返す。そのため、SHA があることでなく、タグが指すコミットと SHA が同じことを確かめる。
  - Dependabot は、SHA で固定した `uses:` を、版のコメントと一緒に書き換える（PR #303 が 3 つのワークフローの `actions/setup-dotnet` をそう書き換えている）。
  - リポジトリの設定 `sha_pinning_required` は `false`（`gh api repos/YUKIKEDA/ElasticLM/actions/permissions`、2026-11-14）。
- 持ち主が決めたこと（2026-11-14）:
  - 問 22-1: §15.2 の「ほかのジョブの actions はタグのまま」を消し、3 つのワークフローのすべての actions を SHA で固定し、版をコメントに書くと書く。SPA のジョブの理由は残す。T25 に範囲（`ci.yml`、`release.yml`、`measure.yml` のすべて）を書く。
  - 問 22-2: `ci.yml` の `actions/setup-dotnet` は、`release.yml` と `measure.yml` と同じ v6.0.0（a98b568…）。`actions/checkout` は v7.0.1（3d3c42e…）、`actions/cache` は v6.1.0（55cc834…）。
  - 問 22-3: スクリプトで、すべてのワークフローの `uses:` が 40 桁の SHA と `# vX.Y.Z` を持ち、`git ls-remote` で引いたタグのコミットと一致することを確かめ、`ci.yml` の `contents: read` のジョブで毎回走らせる。composite の中の `uses:` も確かめる。
  - 問 22-4: 同じスクリプトで、すべての `actions/checkout` が `persist-credentials: false` を持つことも確かめる。
  - 問 22-5: この行は設定を変えない。この行のマージのあと、`main` の CI が通ってから、持ち主が `sha_pinning_required` を有効にし、値を Issue #341 に記録する。
  - 問 22-6: GitHub のワークフローの lockfile は、別の行の候補として `../design-decisions.md` に書く（却下ではない）。
- こちらが決めたこと:
  - スクリプトの置き場所と名前は `eng/ci/Test-ActionPins.ps1`、`ci.yml` のジョブの名前は `pins` にした。ほかのジョブはこのジョブを `needs` で待たない。
  - 形として読めない `uses:` の行（`uses:` を含むのに `<owner>/<repo>[/<path>]@<SHA> # vX.Y.Z` でない行）も失敗にした。読み落とした行が確かめずに通らないようにするためである。ローカルのアクション、`docker://`、再利用のワークフローは今は使わないので、断る。
  - `git ls-remote` の答えは、ref の名前がそのまま同じ行だけを使う（引数は ref の名前の末尾に合うため）。注釈つきのタグは `^{}` の行と比べる。
  - composite の中の composite もたどる。`docker` のアクションは、`runs.image` がダイジェストのない `docker://` のときに失敗にする。今は `docker` のアクションを使わない。
  - composite の中の `actions/checkout` にも、`persist-credentials: false` を求める（今はない）。
  - lockfile の一般提供: Grill のときは preview か一般提供かがはっきりしなかった。実装のときに、2026-10-28 の changelog が generally available と書くことを見つけ、`../design-decisions.md` の記録に書いた（候補として残すことは変えない）。

## 退けた案

Issue #341 の記録には、持ち主が選んだ推奨案 A だけがある。下の「却下した案」は、A を選んだことで取らなかった形を書く。

- **決定:** 3 つのワークフローのすべての `uses:` を、コミットの SHA と版のコメントで固定する。`ci.yml` の `pins` のジョブが、毎回 `eng/ci/Test-ActionPins.ps1` で、形、タグとの一致、composite の中、`actions/checkout` の `persist-credentials: false` を確かめる（持ち主の決定、問 22-1〜問 22-4 の推奨案 A。2026-11-14）。
- **理由:** タグは、アクションのリポジトリを持つ者が別のコミットに付け替えられる。`ci.yml` の `gate` と `aot` は、配る実行ファイルと同じコードを、同じ actions で作ってテストする。その結果は、PR をマージする判断の拠り所になる（§5.1 の「ゲートと計測の結果」、T29）。SHA で固定しても、フォークにだけあるコミットは親のリポジトリの名前で解決されるので、タグとの一致を確かめる。人のレビューだけでは、Dependabot の PR やほかの PR で、タグに戻した行やタグと合わない SHA を見落としうる。
- **却下した案:**
  - `ci.yml` の actions をタグのまま残す（V1d22 の前の §15.2 の形）。タグの付け替えで、ゲートで動くコードが変わる。
  - 確かめを人のレビューと、リポジトリの設定 `sha_pinning_required` だけに任せる。設定は SHA で固定することを求めるが、SHA がタグを指すことを確かめるとは書かれていない（設計 §20.5 が引く GitHub の頁）。
  - この行で `sha_pinning_required` を有効にする（問 22-5 の A でない形）。設定は持ち主のもので、`main` の CI が SHA の形で通ってから有効にする。
  - この行でワークフローの lockfile に移る（問 22-6 の A でない形）。候補として `../design-decisions.md` に残した。
