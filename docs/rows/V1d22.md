## 退けた案

- **決定:** 3 つのワークフローのすべての `uses:` を、コミットの SHA と版のコメントで固定する。`ci.yml` の `pins` のジョブが、毎回 `eng/ci/Test-ActionPins.ps1` で、形、タグとの一致、composite の中、`actions/checkout` の `persist-credentials: false` を確かめる。この行のマージのあと、持ち主が `sha_pinning_required` を有効にする。ワークフローの lockfile は、別の行の候補として残す（持ち主の決定、問 22-1〜問 22-6 の推奨案 A。2026-11-14）。ワークフローと composite の定義は、YAML のパーサー（YamlDotNet）で読む（持ち主の決定、PR #445 の 2 回のレビューのあと、2026-11-14）。
- **理由:** タグは、アクションのリポジトリを持つ者が別のコミットに付け替えられる。`ci.yml` の `gate` と `aot` は、配る実行ファイルと同じコードを、同じ actions で作ってテストする。その結果は、PR をマージする判断の拠り所になる（§5.1 の「ゲートと計測の結果」、T29）。SHA で固定しても、フォークにだけあるコミットは親のリポジトリの名前で解決されるので、タグとの一致を確かめる。人のレビューだけでは、Dependabot の PR やほかの PR で、タグに戻した行やタグと合わない SHA を見落としうる。
