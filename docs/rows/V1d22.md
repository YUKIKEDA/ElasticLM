## 退けた案

Issue #341 の記録には、持ち主が選んだ推奨案 A だけがある。下の「却下した案」は、A を選んだことで取らなかった形を書く。

- **決定:** 3 つのワークフローのすべての `uses:` を、コミットの SHA と版のコメントで固定する。`ci.yml` の `pins` のジョブが、毎回 `eng/ci/Test-ActionPins.ps1` で、形、タグとの一致、composite の中、`actions/checkout` の `persist-credentials: false` を確かめる（持ち主の決定、問 22-1〜問 22-4 の推奨案 A。2026-11-14）。
- **理由:** タグは、アクションのリポジトリを持つ者が別のコミットに付け替えられる。`ci.yml` の `gate` と `aot` は、配る実行ファイルと同じコードを、同じ actions で作ってテストする。その結果は、PR をマージする判断の拠り所になる（§5.1 の「ゲートと計測の結果」、T29）。SHA で固定しても、フォークにだけあるコミットは親のリポジトリの名前で解決されるので、タグとの一致を確かめる。人のレビューだけでは、Dependabot の PR やほかの PR で、タグに戻した行やタグと合わない SHA を見落としうる。
- **却下した案:**
  - `ci.yml` の actions をタグのまま残す（V1d22 の前の §15.2 の形）。タグの付け替えで、ゲートで動くコードが変わる。
  - 確かめを人のレビューと、リポジトリの設定 `sha_pinning_required` だけに任せる。設定は SHA で固定することを求めるが、SHA がタグを指すことを確かめるとは書かれていない（設計 §20.5 が引く GitHub の頁）。
  - この行で `sha_pinning_required` を有効にする（問 22-5 の A でない形）。設定は持ち主のもので、`main` の CI が SHA の形で通ってから有効にする。
  - この行でワークフローの lockfile に移る（問 22-6 の A でない形）。候補として `../design-decisions.md` に残した。
