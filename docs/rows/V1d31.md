## 退けた案

- **決定:** 書き出しの確かめの p99 が 20 ms を超えたジョブは、有効化の p99 の判定から外し、残りのジョブで判定する。1 つも残らなければ失敗にする。外したジョブは Report に書く（持ち主の決定、問 31-1 と問 31-2 の推奨案 A。2026-11-14。設計 §4.2、§20.7）。
- **理由:** 60 ジョブで、書き出しの p99 が 20 ms を超えたジョブと、有効化の p99 が 50 ms を超えたジョブは、ちょうど同じ 12 ジョブだった。2 つの組のあいだ（書き出しの p99 が 7.97 ms と 24.13 ms のあいだ）にジョブはなく、20 ms は道具がもう使っているしきい値である。目標を外れたのは、ディスクの遅いジョブだけだった。判定から外したジョブの値は Report に残るが、目標とは比べない。比べるのは人である。正常なディスクのジョブで外れれば、いまと同じく落ちる。
- **受け入れた限り（独立レビューの M1。持ち主の決定、2026-11-14）:** 書き出しの確かめは製品と同じディスクに書くので、遅いランナーのディスクと、製品が足した書き込みを見分けられない。ディスクの遅いジョブにだけ出る製品の遅れは判定されない。製品の変更で 1 つか 2 つのジョブが 20 ms を超えれば、そのジョブは外れる（3 つとも超えれば落ちる）。3 つとも超えて落ちたときは、一度だけ測り直し、また落ちれば `main` の最新の `Measure` の書き出しの p99 と比べる（`.cursor/rules/workflow.mdc` に書いた）。
- **却下した案:**
  - 3 つのジョブの中央の値で判定する。ディスクの遅いジョブが 2 つある実行は 20 のうち 2 回あり、中央の値がディスクの遅いジョブの値になる（run 43273437584 では 90.38 ms、run 43433230281 では 93.85 ms）。また、正常なディスクのジョブ 1 つで目標を外れても、中央の値では見えなくなる。
  - いまのまま、目標を外れたら落として、人が測定からやり直す。20 の実行のうち 10 にディスクの遅いジョブがあり、そのうち 3 回は目標を外れた。製品の速さに関わらない理由で PR の `Measure` が落ち、流し直すたびに測定のジョブの全体（見込みは約 28 分、§20.7）をもう一度走らせることになる。
