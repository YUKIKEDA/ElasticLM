## 退けた案

- **決定:** 必須の検査は、すべての PR で走る CI の 8 個と Release の 21 個にする（21-1、21-7）。
- **理由:** 必須の検査は、走らなければ Pending のままマージを止める。CodeQL の `Analyze (*)` は Dependabot の PR で走っていない。`Measure` は `paths` で絞られる。タグのときだけのジョブは PR では何も確かめない。
- **却下した案:** CodeQL（default setup）の `Analyze (*)` を必須にするか、規則 `code_scanning` を足す。Dependabot の PR が止まるため。`Measure` とタグのときだけのジョブも必須にする。

- **決定:** loose にする（21-4）。
- **理由:** strict は、`main` が進むたびに、開いているすべての PR に `main` を取り込む push と 29 個の検査のやり直しを求める。行を並べて進める今の進め方（`.cursor/rules/workflow.mdc` の「Rows in parallel」）では、マージのたびにほかの PR がやり直しになる。組み合わせの不具合は、マージのたびに読む `main` の CI で見つける。
- **却下した案:** strict（「Require branches to be up to date before merging」）を入れる。

- **決定:** 迂回できる者は空のままにし、Dependabot の PR にも例外を置かない（21-6、21-8）。
- **理由:** 迂回を許すと、持ち主のトークン（エージェントが使う）でも、検査の通っていない PR をマージできる。ときどき落ちるテストは、今の規則どおり Issue と 1 回の流し直しで扱う。
- **却下した案:** 持ち主か Dependabot を迂回できる者に入れる。

- **決定:** 端末の `gh` のトークンは、今の OAuth のトークンのままにし、§5.4 で受け入れる（21-10、21-12）。
- **理由:** PR #334 の問 7 の持ち主の決定のとおり。エージェントは、Issue、ブランチ、PR、Issue への記録にこのトークンを使う。
- **却下した案:** 範囲を絞ったトークン（fine-grained の PAT など）に変える。

- **決定:** 必須の検査は、出どころを GitHub Actions（15368）に限る（21-3）。
- **理由:** 出どころを限らなければ、同じ名前の状態をほかの app が送っても、必須の検査が満たされる。
- **却下した案:** 出どころを「any source」にする。
