# V1d19（Issue #338）: サーバーのライセンスキーを、コマンドラインの引数に残さずに渡せるようにする

## Grill の記録

Issue #338 のコメント「V1d19 の Grill」に、持ち主の答え（2026-11-14、問 19-1〜19-4 のすべてが推奨案）がある。設計の本文（`../design.ja.md`）は §13.7 の「サーバーのライセンスキーの受け取り方」、§5.4 の `ELM_LICENSE_KEY` の行、§16 の表と鍵のパスフレーズの段落、§20.7 の手順を流す仕組みの `env` の項目（V1d19）を持つ。

### 測った事実（`origin/main` の 5e026d0。行の番号は、そのときのもの）

- サーバーのライセンスキーを受け取るのは、`elm server activate` の引数 `<license-key>`（`ServerLicenseCommands.cs` の 36、39、53 行）と、`elm server activate-request --key`（223、226、241 行）だけである。`src/ElasticLM.Cli` に `ELM_LICENSE_KEY` はなく、標準入力を読む所もない。
- 隠して聞く入力は `CliHost.ReadSecret`（`CliHost.cs`。入力がリダイレクトされていれば `null`）で、鍵のパスフレーズ（`CliSupport.cs` の `Passphrases`）だけが使う。パスフレーズは、変数 → 対話で隠して聞く → 対話でなければ「Set the passphrase in the environment variable …; input is not interactive.」と終了コード 2、の順である。空の変数はないものとして扱う。
- System.CommandLine 2.0.14 は、知らない語を、語そのものを入れた誤りにする。5e026d0 の `elm` で `elm server refresh-request --key ELM-AAAAA-BBBBB-CCCCC-DDDDD --product x --out a.elmreq` を走らせると、標準エラーは「error: Unrecognized command or argument '--key'.」「error: Unrecognized command or argument 'ELM-AAAAA-BBBBB-CCCCC-DDDDD'.」「Run 'elm --help' for usage.」で、終了コードは 2 だった（Windows 11、Debug の JIT）。前の形をなくしただけでは、癖で打ったキーが標準エラーに出る。
- 手順を流す仕組み（`eng/docs/Test-GuideSteps.ps1`）は、`env` に `ELM_API_KEY` だけを受け（712 行）、値を 1 つ（`$state.ApiKey`）持つ。`elm` の行は標準入力をリダイレクトして閉じる（936 行、`Invoke-Step`）ので、`elm` は対話でないと見る。
- Linux: `/proc/<pid>/cmdline` は、`hidepid` の既定（0）でほかの利用者も読める（proc(5)）。`/proc/<pid>/environ` は PTRACE_MODE_READ_FSCREDS の確かめを通る者だけが読める（proc_pid_environ(5)）。Windows: ほかのプロセスのメモリーを読むには、そのプロセスの DACL に照らして `PROCESS_VM_READ` が要り、DACL は作った者のトークンから来る。`SeDebugPrivilege` を持つ者はどのプロセスも開ける（Microsoft Learn の Process Security and Access Rights）。出典の URL を §13.7 に書いた。
- 確かめていないこと（Grill のときのまま）: FlexNet、Keygen、Cryptlex の CLI がキーをどう受け取るか。この行の形は、どれにも頼らない（パスフレーズの形をそのまま使う）。

### 持ち主が決めたこと（2026-11-14、すべて推奨案）

- 問 19-1: キーは環境変数 `ELM_LICENSE_KEY`（名前は固定。名前を変えるオプションは作らない）を先に読み、なければ隠して聞く。入力が対話でなく、変数もなければ終了コード 2。パスフレーズと同じ形（§16）。
- 問 19-2: `elm server activate <license-key>` と `activate-request --key` をなくす。まだリリースがなく、使っている人はいない。
- 問 19-3: `eng/docs/Test-GuideSteps.ps1` の `env=` が `ELM_LICENSE_KEY` も受けるように広げ、頁は変数を設定する手順を、コードブロックの外の文で書く（V1c3b の `ELM_API_KEY` と同じ）。変えた頁は 2 つのレビューを受ける。
- 問 19-4: サンプルは、キーを引数で受け取るままにし、頁に「本物のアプリは、キーを画面か入力で受け取り、引数で受け取らない」と書き足す（R8-D11 の直し）。

### こちらが決めたこと

- 前の形の断り方: `activate` と `activate-request` は、知らない語を構文の誤りにせず（`TreatUnmatchedTokensAsErrors = false`）、コマンドの最初で `ParseResult.UnmatchedTokens` を見て、語を出さない 1 行「An argument is not recognized; elm server <コマンド> takes the license key from ELM_LICENSE_KEY, or asks for it.」と終了コード 2 で止まる。上の測った事実のとおり、既定の誤りの文は語を出すためである。ほかの `elm` のコマンドは今のまま（キーを受け取らないので、出す語にキーは入らない）。
- 読む時: 手元の確かめ（フォルダー、ソケットのパス、`--service`、`activate-request` の状態の問い合わせと `--out`、インストール鍵、`ActivationClient` を作れること）のあと、有効化の操作を呼ぶ直前。あとで断られる入力のためにキーを聞かない。`ActivationClient` はロックを操作の中で取る（`ActivationClient.WithLockAsync`）ので、人が打つあいだロックは持たない（設計のコミット 15cc15e では「`ActivationClient` を作る前」と書いたが、コードを読んで、作れることの確かめのあとに移した）。
- 値は、前後の空白を除かずにそのまま渡す（引数で受け取っていたときと同じ）。空の値の誤りの文は「The license key must not be empty.」（引数のときの「<license-key> must not be empty.」と「--key must not be empty.」に替わる）。
- 聞くときの文は `License key: `（パスフレーズの `Passphrase for …: ` と同じく標準エラーに出す）。
- 手順を流す仕組み: 変数ごとに最後に取った値を持ち、`steps:after` の頁へ両方を引き継ぐ。プレースホルダーに使った名前の誤りの文は、どの変数かを言わない「<名前> was captured with env and fills no placeholder.」にした。
- 問 19-4 の文は、サンプルのアプリが初めてキーを受け取る Tutorial 2（`tutorials/activate-an-app-online.md`）に置いた。キーをサンプルに渡す How-to の頁（`activate-a-device-without-a-network.md`、`deactivate-a-device.md`、`revoke-a-license.md`、`rotate-the-signing-key.md`、`run-without-a-network.md`、`handle-errors.md`）は、どれも `steps:after` で Tutorial 2 のあとに読む頁で、この注意を言い直していない。

### 手順を流す仕組みの試験

`eng/docs/Test-GuideSteps.ps1` を、この行の Debug の `elm` と `elm-server`（scratchpad に写したもの）で、試験用の頁（`docs/guide/tutorials/zz-key-*.md` と、同じ中身の日本語の頁。流したあと消した。コミットしていない）に流した。

- 成功の側: `elm-server` を 1 度起動してインストール鍵を作り、`env=ELM_LICENSE_KEY` で値を取る前の `elm server activate-request` は終了コード 2、取ったあとは 0 で `request: after.elmreq` を出した。スクリプトの終わりに、スクリプト自身の環境に `ELM_LICENSE_KEY` はなかった。
- 断る入力: `env=ELM_OTHER` は「env takes ELM_API_KEY or ELM_LICENSE_KEY only.」、`env` で取った名前を `steps:run` の行と `steps:file` の中身に使うと「<license-key> was captured with env and fills no placeholder.」で、どれも流す前に落ちた。
- 変異: `New-StartInfo` が `ELM_API_KEY` だけを渡す形では、成功の側の頁が「elm server exited with 2.」で落ちた。

### 同じ種類を探した範囲

- `src/` で、秘密（ライセンスキー、API キー、パスフレーズ、ノンスの秘密）をコマンドラインの値で受け取る所: `elm` のほかのコマンドにはない（API キーは `ELM_API_KEY`、パスフレーズは `--passphrase-env` の変数か対話、ノンスの秘密はファイル）。`elm-server` と `elm-service` は、秘密を設定ファイル、環境変数、ファイルから読む。
- 利用者の文書で `elm server activate <…>` と `--key` を書く所: `reference/elm-cli.md` と `how-to/activate-a-server-license-with-elm-service.md`（英語と日本語）だけで、どちらも直した。ほかの頁が `elm server activate` を名指す所（overview、renew-a-server-license、server-configuration、administration-api、formats）は、キーの渡し方を書いていない。
- この 2 つのコマンドの外で、キーが標準エラーに出る道が 2 つ残る（PR #469 のレビューの K5）。どちらも、この行の範囲（`activate` と `activate-request` がキーを受け取る形）の外とした。1 つは、コマンドの名前を打ち間違えたとき（`elm server activat ELM-…`）で、System.CommandLine は `elm server` の知らない語として「Unrecognized command or argument '<語>'.」と出す。もう 1 つは、キーをほかのオプションの値に置いたとき（`--service ELM-…`）で、`--service` の形の誤りの文が値を出す。どちらも、キーをコマンドラインに置いたあとの誤りで、置いた時点でシェルの履歴とプロセスの一覧には出ている。
- `refresh-request` の要求ファイルはキーを持たないので、秘密の形にしなかった。`deactivate-proof` の証明と `elm offline process` の答えも、キーを持たない。
- 利用者の文書の「何も表示されない」（Tutorial 2 の `ELM_API_KEY`）: PowerShell の `Read-Host -MaskInput` は 1 文字ごとにアスタリスクを出す（Microsoft Learn の Read-Host、「displays asterisks (`*`) in place of the characters」。`-MaskInput` は PowerShell 7.1 から）。同じ種類として、Tutorial 2 の文も直した。
- サンプルがキーを引数で受け取る頁は、上の「こちらが決めたこと」のとおり。

## 退けた案

- **決定:** キーは `ELM_LICENSE_KEY` を先に読み、なければ隠して聞く（問 19-1）。
- **理由:** パスフレーズと同じ形で、新しい入力の形を足さない。手順を流す仕組みは、変数を `elm` の行に渡せる。
- **却下した案:**
  - 標準入力（`--key-stdin`）。`elm` に新しい入力の形を足し、手順を流す仕組みが標準入力を渡せない。
  - ファイル（`--key-file`）。`../design-decisions.md` の `--api-key-file` の却下と同じ形。

- **決定:** 引数の形（`activate <license-key>`、`activate-request --key`）をなくす（問 19-2）。
- **理由:** まだリリースがなく、使っている人はいない。
- **却下した案:** 残して警告する。漏れる道が残る（PR #334 の問 4 で退けた B と同じ）。

- **決定:** 頁は、変数を設定する手順を文で書き、手順を流す仕組みは `env=ELM_LICENSE_KEY` で値を渡す（問 19-3）。
- **理由:** CI で頁の手順を流し続ける。
- **却下した案:** 頁では流さず、文で書くだけにする。CI で確かめなくなる。

- **決定:** サンプルは引数で受け取るままにし、頁に注意を書く（問 19-4）。
- **理由:** 手順を流す仕組みが、サンプルの行に変数も打った値も渡せない。
- **却下した案:**
  - サンプルも環境変数で受け取る。仕組みが `dotnet` の行に変数を渡せない。
  - サンプルも隠して聞く。仕組みが打てない。

- **決定:** 前の形を、語を出さない誤りで断る（こちらの決定）。
- **理由:** System.CommandLine の既定の誤りは、知らない語をそのまま出すので、癖で打ったキーが標準エラーと CI のログに残る。
- **却下した案:** 既定の誤り（「Unrecognized command or argument '<語>'.」）のままにする。上の理由のとおり、キーを出す。
