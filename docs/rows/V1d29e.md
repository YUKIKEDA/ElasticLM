# V1d29e（Issue #480）: マシン ID の、除く ID の規則と `/etc/machine-id` の大きさの規則をテストする

## Grill の記録

Issue #480 の Scope が、この行の Grill で決める点（§20.7 の表の V1d29e の行）に答えを持ち、設計 §10.3 は読み手の形を決めていないので、Grill は開かなかった（`workflow.mdc` の 1）。Issue は、持ち主の決定（2026-11-22、Issue #348 の最後のコメントの 4、[V1d29.md](V1d29.md) の問 4 の案 A）で立った。

### 測った事実（`origin/main` の 5a23241）

- `MachineIdSources.AddIfValid`（95〜114 行）と `ReadLinuxMachineId`（116〜131 行）は `private` で、呼ぶのは `ReadAll` だけだった。`ReadLinuxMachineId` は、もとからファイルのパスを引数に取る。`ElasticLM.Licensing.Tests` は `InternalsVisibleTo` を持つ。
- `ParseLinuxMachineId` は `TrimEnd('\n')` で末尾の改行をいくつでも除く。XML の文書は「改行は 1 つまで」と書いていた。そのため、ID の 32 文字と改行 32 個の 64 バイトのファイルは ID として読め、改行 33 個の 65 バイトは大きさの規則だけで断られる。大きさの規則の両側を、読める中身で確かめられる。
- `new FileInfo(path).Length` は、ファイルがないときとフォルダーのときに `FileNotFoundException`（`IOException`）を投げる（Windows 11 と、下の Linux のコンテナーで、`info.Exists` を外した変異 R3 が生き残ったことで確かめた）。`info.Exists` の確かめは、`IOException` の `catch` と同じ結果を出す、2 つ目の確かめだった。
- `mcr.microsoft.com/dotnet/sdk:10.0` のイメージの `/etc/machine-id` は 0 バイトのファイルである（`wc -c`）。前からの `Compute_ThisMachine_ReturnsStableFingerprints` は、ファイルがないときだけ飛ばすので、このイメージで落ちた（main でも同じ）。

### こちらが決めたこと

- 2 つを `internal` にし、形は変えない（`AddIfValid(List<byte[]>, byte[]?)` と `ReadLinuxMachineId(string path)`）。
- テストは `MachineFingerprintTests` に置く。このクラスは、もとから `MachineIdSources` のテスト（`ParseLinuxMachineId`、`ParseSmbiosSystemUuid`）を持つ。テストのフォルダーは `%TEMP%` の下に作り、テストごとに消す（`FileClockGuardTests` と同じ形）。
- `ReadLinuxMachineId` から `info.Exists` を外した（`testing.mdc` の「同じ検査が 2 つある」）。読む ID は変わらない。
- `ParseLinuxMachineId` の XML の文書を、コードのとおり「末尾の改行は除く」に直した（動きは変えない。Issue の「変えないこと」）。
- `Compute_ThisMachine_ReturnsStableFingerprints` は、`/etc/machine-id` が空のときも飛ばす（machine-id(5) は、イメージには空のファイルを置くとする）。中身があって読めないときは飛ばさないので、CI の Linux の読み手の誤りは隠さない。
- 同じ種類を探して（`similar-findings.mdc`）、すでに `internal` の `ParseSmbiosSystemUuid` の、テストのない 4 つの規則にもテストを足した（下の表）。

### 設計の文とテスト

設計 §10.3 が書くのは「OS の ID が読めないとき（ファイルがない、`uninitialized`、全ゼロ）は、その指紋を作らない」だけである。全部 1、16 バイトでない ID、64 バイトの上限、SMBIOS の構造の規則は、設計に文がない。テストの remarks はそう書く（`spec-checks.mdc`）。設計に足すかは、持ち主への問い（下）。

| 文、規則 | テスト |
| --- | --- |
| §10.3: 全ゼロの ID は指紋を作らない。コード: 全部 1 と、16 バイトでない ID と、`null` も除く | `MachineFingerprintTests.AddIfValid_EachId_KeepsOnlyA16ByteIdThatIsNeitherAllZerosNorAllOnes`（`null`、15 と 17 バイト、全部 00、全部 FF、先頭だけ 01 の 00、先頭だけ FE の FF、00 の後に FF、ふつうの ID） |
| コード: 64 バイトを超える `/etc/machine-id` は読まない | `ReadLinuxMachineId_FileSize_ReadsAtMost64Bytes`（33、63、64 バイトは読め、65 バイトは `null`） |
| §10.3: ファイルがないときは指紋を作らない。コード: フォルダー、ほかが開いている、読む権限がないときも `null` | `ReadLinuxMachineId_FileNotReadable_ReturnsNull`（`missing`、`folder`、`FileShare.None` で開いた `locked`、Windows は読み取りを拒む ACE、Linux と macOS はモード 000 の `denied`。root では `denied` を飛ばす） |
| §10.3: `uninitialized` | 前からの `ParseLinuxMachineId_Contents_FollowFormat` |
| コード: SMBIOS の type 1 で 0x18 バイトに足りない構造は飛ばす、終わりの構造（type 127）で止まる、長さが 4 未満の構造と表の外へ出る構造は `null` | `ParseSmbiosSystemUuid_ShortOrMalformedStructures_FollowTheirRules`（表の終わりちょうどで終わる構造と、1 バイト外へ出る構造を含む） |

### 変異の確かめ

Windows 11 で、`MachineIdSources.cs` を 1 つずつ変え、`ElasticLM.Licensing.Tests` を作り直して `MachineFingerprintTests` を流した（ビルドの終了コードを見てから、テストの終了コードで決めた。1 回 120 秒の上限）。どれも作れ、どれも落ちた。

| 変異 | 落ちたテスト |
| --- | --- |
| A1 `id.Length != 16` → `< 16` | `AddIfValid_…` |
| A2 `id.Length != 16` → `> 16` | `AddIfValid_…` |
| A3 `allZero &= b == 0x00` → `b == 0x01`（全ゼロを見つけない） | `AddIfValid_…` |
| A4 `allOnes &= b == 0xFF` → `b == 0xFE`（全部 1 を見つけない） | `AddIfValid_…` |
| A5 `allZero &=` → `allZero =`（最後のバイトだけを見る） | `AddIfValid_…` |
| A6 `allOnes &=` → `allOnes =` | `AddIfValid_…` |
| A7 `!allZero && !allOnes` → `\|\|` | `AddIfValid_…` |
| R1 `Length <= 64` → `< 64` | `ReadLinuxMachineId_FileSize_…` |
| R2 `Length <= 64` → `<= 65` | `ReadLinuxMachineId_FileSize_…` |
| R4 `catch (IOException)` に `when (path.Length < 0)` | `ReadLinuxMachineId_FileNotReadable_…`（Windows: `missing`、`folder`、`locked`） |
| R5 `catch (UnauthorizedAccessException)` に `when (path.Length < 0)` | `ReadLinuxMachineId_FileNotReadable_…`（`denied`） |
| S1 `length < 4` → `< 2` | `ParseSmbiosSystemUuid_ShortOrMalformedStructures_…` |
| S2 `offset + length > table.Length` → `>=` | 同上 |
| S3 `offset + length > table.Length` → `> table.Length + 1` | 同上 |
| S4 `length >= 0x18` → `>= 0x17` | 同上 |
| S5 `type == 127` → `type == 126` | 同上 |

R3（`info.Exists` を、いつも真の `path.Length > 0` にする）は、外す前のコードで生き残った。上の「測った事実」のとおり 2 つ目の確かめだったので、テストを足さずに外した。`id is null` の腕は、外すと null 許容の警告（CS8602）で作れないので、変異にしていない。

Linux は、WSL のコンテナー（`wslc` 3.0.5、`mcr.microsoft.com/dotnet/sdk:10.0`）で、作業ツリーの写しをコンテナーの中に写し、root でない利用者として流した。元のコードで 28 件のうち 27 件が通り、`Compute_ThisMachine_ReturnsStableFingerprints` が飛んだ（空の `/etc/machine-id`）。R4 は `missing`、`folder`、`locked` で、R5 は `denied` で落ちた。macOS は CI の `build.ps1 (macos-latest)` が流す。

### 同じ種類を探した範囲

`MachineIdSources.cs` のすべての読み手と解析（`ReadAll`、`ParseLinuxMachineId`、`ParseSmbiosSystemUuid`、`AddIfValid`、`ReadLinuxMachineId`、`ReadWindowsMachineGuid`、`ReadWindowsSmbiosUuid`、`ReadMacPlatformUuid`）と、`MachineFingerprint.cs` を読んだ。テストのない規則で、この PR で足さなかったものは次の 3 つで、どれも OS の API を呼ぶ `private` の中にある（持ち主への問い 2）。

- `ReadWindowsMachineGuid`: 64 ビットのレジストリのビューを読むこと（§10.3 の文）、`Guid.TryParse` で読めない値を除くこと、ビッグエンディアンのバイトの並び。
- `ReadWindowsSmbiosUuid`: `GetSystemFirmwareTable` の大きさが 8 バイト以下か 1 MiB を超えれば読まないこと、2 回目の呼び出しの大きさが違えば除くこと、`RawSMBIOSData` の表の長さが 0 以下か残りの大きさを超えれば除くこと。
- `ReadMacPlatformUuid`: `IOPlatformUUID` を `Guid.TryParse` で読み、ビッグエンディアンで並べること。

### 持ち主への問い

1. **設計 §10.3 の文**: §10.3 は「全ゼロ」だけを書き、全部 1、16 バイトでない ID、64 バイトを超える `/etc/machine-id` を読まないこと、SMBIOS の構造の規則を書かない。V1d29 の問 4 の案 A は「§10.3 の規則が、テストで固定される」と書いた。
   - A（推奨）: §10.3 の「OS の ID が読めないとき」の括弧に「16 バイトでない、全部 0 か全部 1」を足し、「`/etc/machine-id` は 64 バイトを超えれば読まない（末尾の改行は除いて読む）」を足す。この PR に入れ、独立した設計の読み直しを通す。利点: テストが設計の文を確かめる形になる。欠点: 設計の差分の読み直しが要る。
   - B: 設計は変えず、テストの remarks が「設計は書かない」と書くまま（この PR の今の形）。利点: 設計の差分がない。欠点: 規則がコードとテストにしかない。
2. **OS の API の中の規則（上の 3 つ）**:
   - A（推奨）: 行を足し、OS の API から得たバイトや文字列を解く部分（レジストリの値、`RawSMBIOSData` の頭、`IOPlatformUUID` の文字列）を `internal` の関数に分けてテストする。利点: 3 つの OS の読み手が同じようにテストされる（`similar-findings.mdc` の「Windows、Linux、macOS のマシン ID の読み手」）。欠点: 製品のコードの分け方が変わる。
   - B: 今のまま、CI の 3 つの OS の `Compute_ThisMachine_ReturnsStableFingerprints` に頼る。利点: 変更がない。欠点: 規則を外しても落ちるテストがない。

## 退けた案

- **決定:** 2 つを、形を変えずに `internal` にする。
- **理由:** Issue の「読む ID と指紋は変わらない」を守り、差分を最小にする。`ReadLinuxMachineId` は、もとからパスを取る。
- **却下した案:** `AddIfValid` を `bool IsValid(byte[]?)` に変える。呼ぶ所が変わり、テストの対象が `ReadAll` の使い方と離れる。

- **決定:** `info.Exists` を外す。
- **理由:** 外しても結果が変わらない 2 つ目の確かめで、変異 R3 が生き残った（`testing.mdc`）。
- **却下した案:** 残してテストを足す。結果で見分けられる入力がない。

- **決定:** テストを `MachineFingerprintTests` に足す。
- **理由:** このクラスが、もとから `MachineIdSources` のテストを持つ。
- **却下した案:** `MachineIdSourcesTests` を新しく作る。`MachineIdSources` のテストが 2 つのファイルに分かれる。
