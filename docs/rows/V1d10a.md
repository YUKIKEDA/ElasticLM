## Grill の記録

## 退けた案

- **決定:** `ci.yml` と `measure.yml` の `admin-ui-dist` と、`measure.yml` の `measure-bin` を、作ったジョブがジョブの出力で渡した SHA-256 と照らす。`measure-bin` は、それだけのフォルダーに取って照らしてから展開する。`measure-run-<N>` は照らさず、§5.4 で受け入れる（持ち主の決定、問 10a-1〜問 10a-3 の推奨案 A。2026-11-14。設計 §5.3 の T29、§5.4、§20.5 の「ジョブの間の artifact の確かめ」）。
- **理由:** 同じ実行のどのジョブも、ほかのジョブの artifact を同じ名前で置き換えられる（T22、PR #388 の実行 43367452071 で測った）。`ci.yml` と `measure.yml` の artifact は公開されないが、置き換えれば、ほかのジョブのゲートと計測の結果を変えられる。その結果は、PR をマージする判断と、§4.2 に書く値の拠り所になる（§5.1）。`release.yml` の確かめと同じ文面の段を使えば、通る道はもう `release.yml` の実行が同じランナーの種類で示している。`measure-run-<N>` は 1 つの matrix の 3 つのジョブが上げ、matrix のジョブは出力を共有するので、出力と照らしてもジョブどうしを分けられない。
- **却下した案:** Issue #389 には持ち主の答えだけがあり、問の選択肢の文面はない。下は、答えと Issue の Task が名指す、選ばなかった形である。
  - 問 10a-1 と問 10a-2 の (B): 照らさず、§5.4 に受け入れると書く（Issue の Task の「受け入れるか」）。ほかのジョブの結果を変えられることが残り、`measure-bin` はチェックアウトの上に取られたままで、置き換えた artifact が `run.ps1` を上書きできる。
  - 問 10a-3 の (B): `measure-run-<N>` も、`measure` の出力と照らす。matrix の出力は共有されるので、1 つのジョブはほかのジョブの名前の出力も書け、照らしても守りにならない。`measure` を 3 つのジョブの定義に分ければ分けられるが、V1d7 の `build` の matrix と同じく、ジョブの定義を分けることはしない（V1d7 の問 7-6）。
  - 問 10a-6 の (B): 一時のワークフローで、置き換えた artifact で落ちることをランナーで測る。V1d7 の実行 43367452071 と 43368851526 が、同じ段の文面で、`windows-latest`、`ubuntu-latest`、`macos-latest` を含むランナーで、もう測っている。
  - 問 10a-7 の (B): 3 つのワークフローの段の文面が同じことを、機械で確かめる。この行では、手元で取り出して比べ（上の「手元で確かめたこと」）、そのあとの変更はレビューで見る。
