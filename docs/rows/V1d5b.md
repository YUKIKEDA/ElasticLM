## 退けた案

- **決定:** 答えの届かなかった取得と借り出しは、クライアントが、その要求の証明の `jti` を名指す返却（`DELETE /v1/leases/requests/{jti}`）を送り、サーバーは、その要求で出した同じ鍵のリースだけを消す。届かなければメモリーに 16 件まで残して送り直す。借り出しは早期返却として数える（問 5b-1〜5b-4。設計 §12.7.7）。
- **理由:** 正当な利用（通信の切れ、30 秒の打ち切り、大きすぎる答え、アプリの取り消し）でも、席がリースの期限まで埋まり、2 席の機能では 3 回目の取得が断られた。借り出しは管理者も返せない。答えの届かなかったクライアントはリース ID を知らないので、要求の `jti` で名指す。`jti` で出したリースだけを消すので、中継がほかの持ち手の答えを運んでも、そのリースは消えない（V1d5 の問 5-4 と両立する）。
- **却下した案（Grill の各問の B 以下。持ち主はどれも A を選んだ。2026-11-14）:**
  - 問 5b-1 (B) 取得を冪等にする。クライアントは、答えをなくした取得の `jti` を、機能・席の数・版・期間ごとに覚え、次の同じ取得の `retry` に入れる。サーバーは、その `jti` で出した、同じ鍵の `seq` 1 のリースの最後のトークンを返す（Idempotency-Key の形。draft-ietf-httpapi-idempotency-key-header-08）。席が空くのは、アプリが取得し直したときだけである。答えを大きくする中継は、同じ答えをまた大きくする。`elm-server` のふつうのリースは、再起動で消える。(C) A と B の両方。2 つのサーバーとクライアントに、道が 2 つずつできる。(D) §5.4 に受け入れる。攻撃がなくても、1 回の通信の切れで、席がリースの期間（借り出しは最長でその期間）埋まる。`elm-server` の管理者は借り出しを空けられない。
