## 退けた案

- **決定:** 要求を組む者がマシンの指紋の数だけ試用を取れることを受け入れる（問 26-5）。
- **理由:** 指紋はクライアントが申告する値で、サービスは確かめられない。アプリの検証は端末の側にある。
- **却下した案:** 試用のトークンで、今の指紋のすべてがトークンにあることを求める。指紋が増えた端末（SMBIOS の UUID が後から読めるようになった Windows など）が試用を失い、アプリの改ざんで外せる。

- **決定:** 早期返却の主キーにリース ID を足す（問 26-8）。
- **理由:** 1 行が 1 回の返却になり、数える式（行の数）を変えずに済む。
- **却下した案:** 数の列を足し、`ON CONFLICT DO UPDATE` で数を増やす。数える式と書く式の両方が変わる。
