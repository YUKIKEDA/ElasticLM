# V1d10（Issue #328）: `release.yml` の `publish` が、`SHA256SUMS` に載っていないパッケージも公開することを直す（V1d の指摘 F16）

## Grill の記録

Issue #328 に記録した。問 10-1 と問 10-2。持ち主の決定はどちらも推奨案 A（2026-11-13）。`release.yml` の `publish` が、`SHA256SUMS` に載っていないパッケージも公開し、`SHA256SUMS` そのものを何とも照らさないことを直す。決めた形は設計（`../design.ja.md`）§20.5 の「公開のジョブの確かめ」、脅威は §5.3 の T22 と T24 にある。

- 調べた事実（Issue #328 の記録）: `publish` は、`SHA256SUMS` のパッケージの行だけを確かめ（`grep … | sha256sum --check --strict`）、フォルダーにある `*.nupkg` をすべて push していた。`gh release edit --draft=false` は、下書きのどの配布物も公開する。`SHA256SUMS` そのものは、何とも照らしていなかった。
- 持ち主が決めたこと:
  - 問 10-1: 下書きの Release の配布物の一覧が、`SHA256SUMS` の行の名前と `SHA256SUMS` そのものに、ちょうど一致しなければ、`publish` を止める。
  - 問 10-2: `SHA256SUMS` を、`checksums` のジョブの出力 `sha256sums` と照らす（V1d7 の問 7-4 の出力を使う）。
  - V1d7（Issue #325）のあとに、別の PR にする。
- こちらが決めたこと:
  - V1d7 の独立レビューから足した点（Issue #328 の 2 つ目の記録）: `publish` が取る `image-oci` も、`image-test` と `guide-containers` と同じコマンドで、tar の SHA-256 とフォルダーの中身の一覧を `image` の出力と照らす。index のダイジェストの照らしは、push の段に残す。V1d7 の問 7-1 は、取るジョブがファイルの SHA-256 と照らす形を決め、`image-test` は、設計のレビューのあとで、index のダイジェストに加えてこの照らしを足した。`publish` だけをダイジェストだけで残す理由はなかった。`image-oci` は、ほかの取るジョブと同じく、それだけを入れるフォルダー（`image`）に取る。
  - すべての確かめを、何かを push する前に置く。V1d10 の前は、パッケージを push したあとで `image-oci` を取っていた。今は、下書きの確かめと `image-oci` の確かめのあとに、NuGet へのログインと push が来る。
  - 下書きのすべての配布物を取り、問 10-2 のとおり、`SHA256SUMS` の行のすべてのファイルを照らす。フォルダーの中身が同じ名前の一覧とちょうど同じことも確かめる（`attest` と `draft` と同じ確かめ。`gh release download` は、配布物の一覧を取った呼び出しとは別に Release を読むので、一覧とフォルダーの両方を見る）。
  - 確かめのコマンドは、`attest` と `draft` のコマンドに、配布物の一覧の `diff` を 1 行足したものにした。同じ文の段を `checksums` にも置き、すべての PR で走らせる（V1d7 の「PR で走る場所」の形）。PR では下書きがないので、配布物の一覧には、`draft` が `gh release create` に渡す `assets/*` と同じく、取り直したフォルダーの `*` の名前を書く。そのため PR では、一覧の確かめは、フォルダーの確かめと同じ名前を比べる。一覧が合わないときに落ちることは、下の手元の確かめで見た。
- 手元で確かめたこと（2026-11-13、Windows 11、Git for Windows の bash 5.3.15 と GNU coreutils 8.32 の `sha256sum`。ワークフローの 2 つの段（`checksums` と `publish`）から同じ文であることを確かめて取り出したスクリプトを、見本のフォルダー（2 つの圧縮ファイル、`.nupkg`、`.snupkg`、SBOM、`SHA256SUMS`）で走らせた）: 下書きの確かめは、合うフォルダーと、一覧の順を変えたものでは通る。一覧に配布物を足したもの、一覧から `.snupkg` を除いたもの、一覧から `SHA256SUMS` を除いたもの、空の一覧、中身を変えたファイル、変えたファイルに合わせて書き直した `SHA256SUMS`、末尾に空の行を足した `SHA256SUMS`、パッケージを足して `SHA256SUMS` と一覧にも足したもの、パッケージを足して一覧にだけ足したもの、パッケージをフォルダーにだけ足したもの、SBOM をフォルダーと一覧の両方から除いたもの、`SHA256SUMS` のないもの、空の出力では落ちる（15 の場合）。`image-oci` の確かめは、合う tar では通り、中身を変えた tar、足したファイル、名前を変えた tar、空の出力では落ちる（5 の場合）。どの場合も、結果は期待どおりだった。`actionlint` 1.7.7 は、`main` と同じ 1 件（`windows-11-arm` のランナーのラベルを知らない）のほかに何も出さなかった。
- タグの実行だけが示すこと: `gh release view` と `gh release download` が、下書きの Release を見つけて、すべての配布物を返すこと（`gh` のソースは読んだ。設計 §20.5 の「公開のジョブの確かめ」）。GitHub が配布物の名前を変えないこと。すべての配布物を取る時間が `publish` の `timeout-minutes`（15 分）に収まること。どれも、`publish` が初めて走る V1e のタグの実行で分かる。合わなければ、ジョブは何も push せずに落ちる。
- 同じ種類を探した範囲: `release.yml` の `gh release` と `actions/download-artifact` のすべて。`gh release` を使うのは `draft`（`create`）と `publish`（`view`、`download`、`edit`）だけである。`path` を持たない `actions/download-artifact` は `publish` の `image-oci` だけだったので、`image` のフォルダーに取るようにした。
- この行の外で見つけたもの: ない。

## 退けた案

- **決定:** `publish` は、何かを push する前に、下書きの Release の配布物の一覧とすべての配布物を取り、`SHA256SUMS` を `checksums` のジョブの出力 `sha256sums` と、`SHA256SUMS` の行のすべてのファイルを `SHA256SUMS` と照らし、配布物の一覧が `SHA256SUMS` の行の名前と `SHA256SUMS` にちょうど一致しなければ止まる（持ち主の決定、問 10-1 と問 10-2 の推奨案 A。2026-11-13）。`publish` が取る `image-oci` も、`image-test` と同じく tar の SHA-256 と一覧で照らす（V1d7 の独立レビューから足した点。設計 §5.3 の T22・T24、§20.5 の「公開のジョブの確かめ」）。
- **理由:** `gh release edit --draft=false` は、下書きのどの配布物も公開し、`publish` はフォルダーの `.nupkg` をすべて push する。そのため、`SHA256SUMS` に載っていない配布物があれば、それも公開された。`checksums` の出力は、V1d7 から `attest` と `draft` が照らしている、`SHA256SUMS` を書いたジョブの値で、`publish` は同じ実行の中でそれを読める。`image-oci` の照らし方は、V1d7 の問 7-1 が決めたファイルの SHA-256 の形にそろえた。
- **却下した案:** 問 10-1 の (B) `SHA256SUMS` に載っていないパッケージだけを見る（載っていないほかの配布物が、そのまま公開される）。問 10-2 の (B) `SHA256SUMS` を来歴の証明の検証と照らす（証明は `attest` のジョブが、`SHA256SUMS` の中身を、同じ実行の artifact から作るので、`checksums` の出力と照らすのと同じ値を、証明の検証（`gh attestation verify`）を通して確かめることになる）。`image-oci` の点の (B) 前からのとおり、index のダイジェストだけと照らす（tar のファイルは照らさず、`image-test` と `guide-containers` と形がそろわない）。
