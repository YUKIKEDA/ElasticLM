### 測った事実

一時的なワークフロー `measure-349-services.yml`（PR #532 に足し、ready の前に消した）で、ランナーの systemd と launchd を、`sleep` を回すシェルのスクリプトのジョブで測った。

- Linux（ubuntu-26.04、イメージ 20261122.9.1、systemd 259。run 46123563560 と 46125098742、どちらも同じ結果）:
  - `systemctl show` の `DefaultTimeoutStopUSec=1min 30s`、`DefaultRestartUSec=100ms`。`Type=exec`、`Restart=on-failure`、`RestartSec=5` のユニットの `TimeoutStopUSec=1min 30s`、`TimeoutStopFailureMode=terminate`、`KillMode=control-group`、`KillSignal=15`、`StartLimitIntervalUSec=10s`、`StartLimitBurst=5`、`StandardOutput=journal`。プロセスの今のディレクトリは `/`。
  - `useradd --system --shell /usr/sbin/nologin` は、UID 999、同じ名前のグループ（GID 986）、ホーム `/home/<名前>`（作らない）の利用者を作った。`install -d -o <利用者> -g <利用者> -m 0700` のフォルダーは、その利用者のモード 0700 になった。
  - SIGKILL のあと、ユニットは `activating`、`auto-restart`、`Result=signal` になり、6 秒後には新しいプロセスで `active`、`NRestarts=1` だった。`systemctl stop` のあとは `inactive`、`Result=success`、`ExecMainCode=1`、`ExecMainStatus=0`。
  - ランナーの `/opt` と `/usr/local/bin` は、だれでも書けるモード（`drwxrwxrwx`）だった。頁の置き場所の規則（上のすべてのフォルダーを root だけが書ける）は、このランナーの `/opt` では成り立たない。E2E は頁の名前のまま `/opt/elm-e2e-<数字>` に置く（製品はプログラムの置き場所を確かめない）。
- macOS（macos-latest、macOS 26.7.2、launchd の Darwin Bootstrapper 7.0.0）:
  - 1 回目（run 46123563560 と 46125098742）: `sysadminctl -addUser … -roleAccount` は、`-UID 441` でも `-UID` なしでも「Role account requires specified UID in 450-499 range.」で断り、終了コードは 0 だった。`dscl . -create` で作ったグループと利用者（UID 443）は `id` で見えた。`StandardOutPath` を root のフォルダー（`/Library/Logs`）に置いた plist のジョブは、`last exit code = 78: EX_CONFIG` で始まらなかった。`ExitTimeOut` を書かないジョブの `launchctl print` は `exit timeout = 5`、`minimum runtime = 10` だった。
  - 2 回目（run 46125447012）: `-UID 451 -roleAccount` は「Assigning UID: 451 GID: 20」で作り、グループは `staff` だった。ログのファイルのない plist は動き、ログのファイルを root のフォルダーに置く plist は、launchd のログに「Service could not initialize: posix_spawn(/usr/local/elmmeasure.sh), error 0xd - Permission denied」を残して始まらなかった。launchd は `StandardOutPath` をジョブのアカウントで開く。
  - 3 回目（run 46126030473）: `dseditgroup -o create -i 452` のグループと `sysadminctl … -UID 452 -GID 452 -roleAccount` のアカウントは、`uid=452 gid=452`、シェル `/usr/bin/false`、ホーム `/var/empty`、`IsHidden: 1` だった。root のフォルダーに root がアカウントの持ち主で作った（`install -m 0640 -o … /dev/null`）ログのファイルで、ジョブは動き、書いた。15 秒動いたプロセスを SIGKILL すると 1 秒ほどで、1 秒ほど動いたプロセスでは 9 秒ほどで、launchd は起動し直した。`launchctl kill SIGTERM` で 0 で終わったジョブは `state = not running`、`last exit code = 0` で、起動し直されなかった。`launchctl kickstart` で動き直した。`sysadminctl -deleteUser` は、アカウントとともに、そのグループも消した（あとの `dseditgroup -o delete` は「Group not found.」）。

### こちらが決めたこと

- macOS のアカウントは、`dseditgroup` で専用のグループを作り、`sysadminctl -roleAccount` に `-UID` と `-GID` を渡して作る（問 30-d は、どちらかを試して書くとした）。`-GID` がなければグループが `staff` になり、`dscl` で 1 つずつ作る形は項目を書き漏らしやすいためである。
- launchd のログのファイルは、root のフォルダーに、root がアカウントを持ち主にして先に作る。アカウントが書けるフォルダーにすると、そのフォルダーの中のものをアカウントが置き換えられるためである（設計の独立レビューの D13）。
- 手順のランナーの印は `<!-- steps:e2e tests=<クラス>.<メソッド>,… -->` の 1 行にした（問 30-i の形の細かいところ）。

## 退けた案

- **決定:** `security-model.md` は、`Origin` をブラウザーが送ったときだけ比べると書く（問 30-1）。
- **理由:** 設計の T14 とコード（`ElmService.Web.cs`）がそう決めている。
- **却下した案:** コードで `Origin` を必ず求め、T14 を変える。

- **決定:** §12.6.1 の数を直し、判断（証明より前に `404` を答える）は残す（問 30-3）。
- **理由:** 持ち主の決定。直すのは数の誤りで、判断の理由（有効化の中身は何も返さない）は変わらない。
- **却下した案:** 証明を先に確かめる順に変える。

- **決定:** `elm-server` が Windows のサービスとして動けるようにする行を、サーバーの組に足す（問 30-5、V1d29a）。
- **理由:** 設計 §13.6 は Windows サービスで再起動させると書くが、`elm-server` にはその仕組みがなかった。
- **却下した案:** Windows は別の起動の仕方を書いて設計を変える。Linux と macOS だけを先に書く。

- **決定:** 1 つの PR にする（問 30-6）。
- **理由:** 持ち主の決定。
- **却下した案:** 設計の PR を先に分ける。

- **決定:** systemd は `Type=exec` で動かし、`UseSystemd` と `Type=notify` のための依存は足さない（問 30-g）。
- **理由:** 持ち主の決定（依存を足さない）。
- **却下した案:** `Microsoft.Extensions.Hosting.Systemd` を足して `Type=notify` にする。

- **決定:** データのフォルダーは root が `install -d` で作り、`StateDirectory=` と `DynamicUser=` は使わない（問 30-c）。
- **理由:** 持ち主の決定。
- **却下した案:** systemd にフォルダーと利用者を作らせる。

- **決定:** 手順のランナーに特権の要る行を足さず、頁の手順は 3 つの OS の E2E が確かめる（問 30-i）。
- **理由:** 持ち主の決定。
- **却下した案:** ランナーに `sudo`、`systemctl`、`launchctl`、`sc.exe`、`New-Service` の行を流させる。

- **決定:** ユニットと plist は `samples/ElmServerService/` に置き、リリースのアーカイブには入れない（問 30-f）。
- **理由:** 持ち主の決定。
- **却下した案:** アーカイブに入れる。
