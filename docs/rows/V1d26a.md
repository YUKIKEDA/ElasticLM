# V1d26a（Issue #376）: 管理 API の経路の ID を、監査の行の `target` にする前に確かめる

## Grill の記録

- 持ち主が決めたこと（2026-11-14、Issue #376 のコメント「V1d26a の Grill」。すべて推奨案）:
  - 問 26a-1: `{id}` を取る管理 API の経路のすべてで、形を確かめる（`TryRouteId`、リースは `IsLeaseId`）。形が違えば探さずに、知らない ID と同じ `404` を返し、監査の行は `target` なしで書く。API キー、管理者、セッションの経路と、`elm-server` の V1d4 と同じ形。
  - 問 26a-2: 利用ログの `{name}` は、ファイルの一覧にある名前のときだけ `target` に書く。ない名前は `target` なしで `404`。
- 測った事実（`origin/main` の c17aaac から切ったブランチ、Windows 11、SDK 10.0.403、ASP.NET Core 10.0.14、Debug。テストのプロジェクトの中の一時のテストで。テストは測ったあとで消した）:
  - 8 つの経路（`GET /v1/admin/licenses/{id}`、`POST /v1/admin/licenses/{id}/suspend`、`GET /v1/admin/licenses/{id}/activations`、`GET /v1/admin/licenses/{id}/leases`、`DELETE /v1/admin/leases/{id}`、`DELETE /v1/admin/trials/{id}`、`GET /v1/admin/products/{id}`、`GET /v1/admin/activations/{id}`）に、下の 19 の値を送り、答えと、その呼び出しの監査の行を読んだ。SQLite と PostgreSQL 18（CI と同じダイジェストの `postgres:18` を WSL のコンテナーで動かした）の結果は、ID の値を除いて同じだった。
  - 直す前の結果（ライセンスの経路の場合。`<L>` はあるライセンスの ID、`<U>` は知らない UUID）:

| 送った `{id}` | 答え | 行の `target` |
| --- | --- | --- |
| `<U>` | `404` | `<U>` |
| `<L>`、大文字の `<L>`、`%0A<L>`、`<L>%0A`、`<L>%20`、`%09<L>` | `200`（そのライセンス） | 小文字の `<L>` |
| `<L>%00`、`%00<L>`、`a%00b` | 本文のない `400` | 行がない |
| `a%0Ab`、`a%0D%0Ab` | `404` | LF、CR LF をそのまま持つ文字 |
| 300 文字、5,000 文字の `a` | `404` | 300 文字、5,000 文字のまま |
| `AAAAAAAAAAAAAAAAAAAAAA`（リースの ID の形）、`AAAAAAAAAAAAAAAAAAAAA%0A` | `404` | そのまま（LF を含む） |
| `%C3%A9`、`%FF`、`%2F` | `404` | `é`、`%FF`、`%2F` |

  - リースの強制返却（`DELETE /v1/admin/leases/{id}`）は、`IsLeaseId` で探すかを決めていたが、`404` の行には経路の文字をそのまま書いた（大文字の UUID、`%0A` の付いた ID も、そのまま）。ほかの UUID の経路も、知らない ID の行には経路の文字を書いた（試用の削除だけは、形の合う ID を書き直していた）。
  - `%00`: Kestrel が、パスを戻すときに断る。dotnet/aspnetcore の v10.0.14 タグの `src/Shared/UrlDecoder/UrlDecoder.cs` の 106〜108 行が「The path contains null characters.」の `InvalidOperationException` を投げ、`src/Servers/Kestrel/Core/src/Internal/Http/Http1Connection.cs` の `catch (InvalidOperationException)` が `ThrowRequestTargetRejected` を呼ぶ。要求はサービスの処理に届かず、監査の行はない。PostgreSQL が U+0000 を保存できない（V1d26 の F43）ことには、経路の値は届かない。
  - `%0A` などの空白: `Guid.TryParseExact` は、読む前に前後の空白を除く（dotnet/runtime の v10.0.14 タグの `src/libraries/System.Private.CoreLib/src/System/Guid.cs` の 449 行、`input = input.Trim()`）。そのため、空白で囲んだ ID は、その ID の実体を指す。行の `target` は読んだ ID から書くので、空白は行に入らない。リースの ID（`IsLeaseId`）は、空白を除かない。
  - 要求の行の長さ: Kestrel の `KestrelServerLimits.MaxRequestLineSize` の既定は 8 KiB（同じタグの `src/Servers/Kestrel/Core/src/KestrelServerLimits.cs` の `_maxRequestLineSize = 8 * 1024`）で、サービスは変えない。直す前は、経路の文字を、8 KiB 近くまで行に書けた。
- こちらが決めたこと:
  - UUID の経路の `target` は、確かめた ID を `ToString("D")` で書き直した文字にする（`ElmService.RouteTarget`）。前からあった試用の削除と同じで、大文字や空白を行に入れない。リースの経路は、`IsLeaseId` を通った文字をそのまま書く（大文字と小文字を区別する ID なので、書き直さない）。
  - `PATCH /v1/admin/products/{id}/features/{featureId}` は、2 つの ID の両方が形に合うときだけ、機能の ID を `target` に書く。
  - 形の違う ID の答えは、前と同じ `404` のままにした（探す前の確かめは、前から `FindLicenseAsync` などが持っていた）。変えたのは行の `target` だけである。

## 退けた案

- **決定:** 形の違う `{id}` は、探さずに知らない ID と同じ `404` を返し、監査の行は `target` なしで書く（問 26a-1）。
- **理由:** API キー、管理者、セッションの経路と、`elm-server` の強制返却（V1d4）がもうこの形で、経路ごとに行の形が変わらない。行に呼び出した側の文字が残らない。
- **却下した案 1:** 経路の文字を、長さで切り、制御文字を置き換えて残す。経路ごとに行の形が変わり、置き換えた文字は、送られた文字とも実体の ID とも違う。
- **却下した案 2:** 形の違う ID を `400` と `ELM_MALFORMED` で断る。§14.5 の API キーの経路の決まり（知らないか形が違えば `404`）と違う。

- **決定:** 利用ログの `{name}` は、ノードのファイルの一覧にある名前のときだけ `target` に書く（問 26a-2）。
- **理由:** 名前は一覧と照らしてから使う（M4d2 の教訓）。一覧にない名前は、どのファイルも指さない呼び出した側の文字である。
- **却下した案:** 一覧にない名前も、`target` にそのまま書く（直す前の形）。CR LF や 8 KiB 近い文字が行に残る。
