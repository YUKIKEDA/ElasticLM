# V1d29d（Issue #479）: `website` の監査の無視の一覧から、もう当たらない minimatch と deepmerge を消す

## Grill の記録

V1d29（Issue #348、PR #476）の T28 の確かめで見つけ、持ち主の決定（2026-11-22、Issue #348 の最後のコメントの 3）で行にした。設計 §20.7 の表は、この行の Grill で決める点を 2 つ挙げる。消す前と後の `pnpm audit` の測り方（Node.js 24）と、§20.7 の V1c1 の形の文の直しである。どちらも Issue #479 の Steps が決めており、製品の振る舞いは変わらないので、問は立てていない。

### 測った事実

測ったのは、`origin/main` の 9661ee7 から切ったこの行のブランチ、Windows 11（build 26300）、Node.js 24.22.2（`web/admin/.node-version`。PATH の既定の Node.js は 26 なので、Volta が入れた 24.22.2 のフォルダーを PATH の先頭に置いた）、Corepack の pnpm 12.13.0、`website/pnpm-lock.yaml` は 9661ee7 のまま（この行は lock を変えない）。日付は 2026-11-27。

- 勧告（`gh api advisories/<ID>`）:
  - GHSA-g3hv-75wg-m249（minimatch）: 範囲は `>= 7.0.0, < 11.0.1`。lock の minimatch は 3.1.5 だけで、当たらない。
  - GHSA-gcqx-w48m-w2h4（deepmerge）: `withdrawn_at` は 2026-11-16T18:55:38Z。取り下げられている。
  - GHSA-w5hq-g745-h8pq（uuid）: 範囲は `< 11.1.1`、`>= 12.0.0, < 12.0.1`、`>= 13.0.0, < 13.0.1`。lock の uuid 8.3.2 が当たる（もう 1 つの uuid 14.0.3 は当たらない）。
- uuid の理由: lock で uuid 8.3.2 に頼るのは `sockjs` 0.3.24 だけで、その `lib/transport.js` は `require('uuid').v4` だけを使う。勧告は buf を渡した v3・v5・v6 なので、理由は成り立つ。
- 消す前の一覧（3 つ）で `corepack pnpm install --frozen-lockfile` のあと `corepack pnpm audit`: 終了コード 0。「1 ignored: 1 moderate」で、無視が効いていたのは 1 件だけだった。
- `auditConfig` を除いた `pnpm-workspace.yaml` の写し（`package.json`、`pnpm-lock.yaml`、`patches/` と一緒にスクラッチのフォルダーに置いた）で `corepack pnpm audit --json`: 終了コード 1。勧告は GHSA-w5hq-g745-h8pq（uuid、`<11.1.1`、moderate、8.3.2）の 1 件だけ。
- 消したあとの一覧（GHSA-w5hq-g745-h8pq だけ）で `corepack pnpm install --frozen-lockfile` と `corepack pnpm audit`（`release.yml` の `site` のジョブと同じコマンド）: 終了コード 0、「1 ignored: 1 moderate」。`corepack pnpm run build` も通った。

### 直したこと

- `website/pnpm-workspace.yaml`: `auditConfig.ignoreGhsas` から GHSA-g3hv-75wg-m249 と GHSA-gcqx-w48m-w2h4 と、そのコメントを消した。もう当たらない ID は消すことを、一覧の上のコメントに足した。
- 設計 §5.4（Dependabot の警告が出ない行）: 受け入れた勧告を uuid の 1 件にした。
- 設計 §20.7 の V1c1 の形: 受け入れの項を uuid だけにし、もう当たらない ID は消す理由（残すと、同じ ID に当たるパッケージがあとで入っても `pnpm audit` が知らせない）を書いた。V1c1 で受け入れていた 2 件と、それを消した理由は、別の項に残した。V1c1 の時点の「8 件」と「受け入れる 3 件」の文は、その時点の記録なので変えていない。

### 確かめ

### 同じ種類を探した範囲

- `website/` のほかの無視: `overrides` の 5 件（serialize-javascript、tinypool）は、この行の対象ではない。上書きを除いた測りはしていない。管理画面（`web/admin/pnpm-workspace.yaml`）には `auditConfig` がない。
- 3 つの ID と、minimatch と deepmerge の名前を、リポジトリの Markdown、YAML、ルール、スクリプトで探した。ほかに出るのは、V1d29 の記録（`V1d29.md` の T28）と、設計 §20.7 の表と §22 の表と roadmap の V1d29d の行で、どれも行の記録なので変えていない。

## 退けた案

- **決定:** 当たらなくなった 2 つの ID を一覧から消し、uuid の 1 つを残す。
- **理由:** `ignoreGhsas` は ID ごとに木の全体に効くので、範囲が変わって当たらなくなった ID（minimatch）を残すと、あとでその範囲に当たる版が入ったときに `pnpm audit` が落ちない。取り下げられた ID（deepmerge）は何も無視しなくなり、残す理由がない。
- **却下した案:** 理由がまだ成り立つので残す。V1d29 の T28 で、Docusaurus の `serve.js` は `serve-handler` に glob を渡さず、`@svgr/plugin-svgo` は deepmerge を呼ばないことは確かめたが、それは今の 2 つのパッケージのことで、同じ ID に当たる別のパッケージや版には言えない。
