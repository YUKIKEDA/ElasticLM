### Grill のときに調べた事実（`origin/main` の e5299d2。ソース、man ページ、文書を読んだ）

- `elm-server` が書くのは、データのフォルダーの中だけである。例外は、利用ログを `log.usage` で外に置いたときと、サーバーライセンスを `license` で外に置き `service.url` があるとき（ライセンスの横に一時ファイルを作って置き換える。§12.6.2）である。
- 製品のコードは `/tmp` を使わない。使うソケットは、AF_UNIX（`admin.sock`）と AF_INET、AF_INET6 である。既定のポート 7070 には特権が要らない。
- V1d30 の `SystemdServiceTests` は、起動、強制終了からの再起動、停止、`status` を通すが、リースの経路は通さなかった。
- macOS の `newsyslog` には、写してから切り詰める形も、回したあとにコマンドを流す形もない。`elm-server` の側にも、ログのファイルを開き直す仕組みはない。
- Linux のジャーナルは journald が回す（journald.conf(5)）。Windows は Application のイベントログに書き、ファイルはない。

### こちらが決めたこと

- `newsyslog` の行の、決定にない欄: 数は 7（`.0` から `.6`）、大きさは 10,240 KB、時刻は `*`（大きさだけで回す）にした。これは上限にならない: 回したあと、`elm-server` は `kickstart -k` まで `.0` に書き続け、`newsyslog` が見る新しいファイルは増えないので、次に回すことはない（設計の独立レビューの D2）。持ち主に問 30a-5 を聞き直す（PR #546 の本文）。
- 30a-3 の E2E は、`SystemdServiceTests` の 2 つ目のテスト（`Systemd_HardenedUnit_LendsAndTakesBackALease`）にした。そのテストのサーバーライセンスは、`elm license issue` で 15 秒のリースで発行し、頁の「手で発行したファイル」の置き方（`install -m 0600 -o <利用者>`）で置く。`elm-service` のポリシーの `leaseDuration` は 120 秒以上（`Policies.Members`、§14.5）で、記録のない起動は、今のライセンスの `lease` のあいだ新しいリースを断る（§13.4。`LeaseEngine.EndRecoveryIfFull` で早く終わるのは、回収と借り出しの席が席数に達したときだけで、最初の起動にはない）。1 回目の測りでも、起動からリースまで約 120 秒かかった。E2E の実時間の上限は 1 回の実行で 2 分（§20.7、`RealClock.Budget`）なので、`elm-service` のライセンスでは収まらない。
- 1 回目の測りで、起動から利用ログの `license.refreshed` が見えるまで、どのジョブも 59.8〜60.0 秒かかった。原因は、利用ログの書き込みである: `SignedLog.WriteLine` は行を `FileStream` の緩衝に書き、ファイルに出すのは署名の行のとき（`WriteAuth` の `Flush`）だけで、署名は 60 秒ごと（`ElmServer.SealInterval`）に来る。更新そのものは起動の直後に済んでいる。2 つ目のテストは利用ログを止めたあとに読むので、この待ちはない。

### 書かない項目と理由

- `DynamicUser=` と `StateDirectory=`: 問 30-c が退けた（専用の利用者とデータのフォルダーを root が作る形）。
- `PrivateNetwork=`: 待ち受けと `service.url` の接続を断つ。
- `IPAddressAllow=` と `IPAddressDeny=`: クライアントとサービスのアドレスは配置ごとに違い、見本に書けない。
- `ProtectProc=`、`ProcSubset=`、`PrivateUsers=`、`UMask=`、`SystemCallFilter=` の `~@privileged` と `~@resources`: 1 回目の測りの候補になく、測っていない。問 30a-1 の答えは、測った 20 項目を書くことである。`systemd-analyze security` は、全部をまとめたユニットにも、これらの項目を残りとして示した。足すなら、測ってからにする。

## 退けた案

- **決定:** 見本のユニットに、測った 20 項目をすべて書く（問 30a-1）。
- **理由:** どの項目も、頁の流れ、更新、リース、停止、記録を壊さず（run 46153160165）、サービスの利用者を奪った者ができることを減らす。
- **却下した案:** 測っていない項目まで足す（測らずには推奨できない）。一部だけ書く（壊さない守りを外す。1 項目だけのユニットの点は 6.7〜9.2 だった）。

- **決定:** `RestrictAddressFamilies=` に AF_NETLINK を入れない（問 30a-2）。
- **理由:** 名前解決は AF_NETLINK なしで通り、製品は AF_NETLINK を使わない。
- **却下した案:** AF_NETLINK も入れる（要らない種類のソケットを開ける）。`RestrictAddressFamilies=` を書かない。

- **決定:** 30a-3 のリースは、`elm license issue` の 15 秒のリースのサーバーライセンスで、別のテストにする。
- **理由:** `elm-service` のライセンスのリースは 120 秒以上で、最初の起動の回収の時間が E2E の実時間の上限の 2 分を超える。
- **却下した案:** 頁の流れのテストの中で、`elm-service` のライセンスでリースを取る（上限を超える）。実時間の上限を上げる（§20.7 の決定を変える）。待ちを `RealClock` の外にする（testing.mdc に反する）。
