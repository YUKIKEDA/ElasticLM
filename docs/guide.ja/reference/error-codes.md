# エラーコード

このページには、ElasticLM のすべてのエラーコードを載せる。コードごとに、意味、どの部分が返すか、サーバーがそのコードと一緒に送る HTTP の状態、すべきことを示す。読者は、検証やリクエストの失敗を処理するアプリ開発者と、`elm`、`elm-server`、`elm-service` が出したエラーを読む管理者だ。ライセンスファイルを確かめる順序、つまりどのコードが先に返るかは、[ライセンスファイルと検証](../explanation/license-files-and-verification.md)で説明している。

## コードが届く経路

同じコードが、4 つの経路で届く。.NET では、失敗した検証やリクエストは `LicenseError` を持つ。その `Code` は `ErrorCode` の値で、`WireName` は表にある名前だ。libelasticlm では、数値を返す関数がコードの番号を返す。`elasticlm.h` は、コードごとにその名前のマクロを定義している（`ELM_NO_SEATS` は `40`）。このスレッドのメッセージは `elm_last_error_message` で得られる。`elm-server` と `elm-service` の HTTP API は、エラーを problem 形式のレスポンス（RFC 9457、`application/problem+json`）で返し、その `code` と `title` の項目に名前が入る。`elm` は出力に名前を書く。たとえば `elm license verify` は `invalid: ELM_EXPIRED: The license has expired.` と出力する。コードの名前と番号は、一度公開したら変わらない。新しいコードには、空いている番号を割り当てる。

「返すもの」の列に書く部分は次のとおり。

- **検証**: ライセンスファイル、リーストークン、サーバーの鍵の検証。.NET のライブラリと libelasticlm の両方で行う。
- **クライアント**: .NET のクライアントと libelasticlm のうち、検証以外の処理。アクティベーション、リース、サーバーのピン、保存するファイルを扱う。
- **elm-server**: オンプレミスのライセンスサーバー。クライアントへのレスポンスと、ローカルの管理 API で返す。
- **elm-service**: SaaS 型のアクティベーションサービス。デバイスへのレスポンスと、管理 API で返す。
- **elm**: コマンドラインツール。
- **libelasticlm**: C ライブラリそのもの。呼び出し方の誤りに対して返す。

HTTP の状態は、サーバーがそのコードを HTTP で送る場合に示す。「—」は、そのコードがローカルでしか返らないことを表す。

## コード

| コード | 番号 | HTTP の状態 | 返すもの | 意味 | すべきこと |
| --- | --- | --- | --- | --- | --- |
| `ELM_OK` | 0 | 2xx | すべての部分 | 成功。 | 何もしない。 |
| `ELM_INVALID_ARGUMENT` | 1 | 400 | elm-server、elm-service、libelasticlm | 引数が正しくない。管理 API のクエリの値や本文の項目が正しくない、機能のバージョンが `major.minor[.patch]` の形でない、シート数が 1 から機能のシート数までの範囲にない、借用したリースを更新しようとした、C で出力先が `NULL` か `struct_size` が違う、などだ。 | 呼び出しを直す。メッセージに引数の名前が出る。 |
| `ELM_MALFORMED` | 2 | 400 | 検証、クライアント、elm-server、elm-service、libelasticlm | 入力の形式かサイズが正しくない。有効でないライセンスファイルやトークン、サイズの上限を超えたファイル、解析できないリクエストの本文、壊れた保存済みのアクティベーションファイル、有効でないサーバーのレスポンス、などだ。 | ファイルや本文が想定したもので、欠けていないかを確かめる。保存したアクティベーションが壊れている場合は、管理者にアクティベーションを解除してもらい、もう一度アクティベーションする。 |
| `ELM_UNTRUSTED_KEY` | 3 | — | 検証 | ライセンスやリースにあるどの鍵証明書も、トラストストアのルート鍵でその署名鍵を証明していない。 | アプリが発行元のルート鍵を信頼していることと、ファイルがその発行元のものであることを確かめる。 |
| `ELM_BAD_SIGNATURE` | 4 | — | 検証、elm-server | 署名が検証に通らない、またはトークンが ES256 で署名されていない。`elm-server` は、リースの再登録のレスポンスで、リースごとにこのコードを返す。 | ファイルは書き換えられたか壊れたものとして扱い、発行元から新しいファイルを受け取る。 |
| `ELM_CERTIFICATE_EXPIRED` | 5 | — | 検証 | トークンが、その鍵証明書の有効期間の外で発行された。 | 有効な鍵証明書のもとで署名したファイルを、発行元に求める。 |
| `ELM_CLOCK_TAMPERED` | 6 | — | 検証 | 時計が戻された、またはトークンの発行時刻が未来になっている。 | システムの時計を正しく合わせる。 |
| `ELM_WRONG_PRODUCT` | 7 | 400 | 検証、elm-service | ライセンスやリースが別の製品のものである。`elm-service` では、ライセンスキーがリクエストの製品のものでない。 | この製品のライセンスかキーを使う。 |
| `ELM_WRONG_INSTALLATION` | 8 | — | 検証 | ライセンスやリースが、別のインストール鍵に紐付いている。 | このインストールでアクティベーションするか、このインストール用のライセンスを使う。 |
| `ELM_FINGERPRINT_MISMATCH` | 9 | — | 検証 | マシンフィンガープリントがライセンスと一致しない。 | ライセンスを受けたマシンで動かすか、このマシン用にライセンスを発行し直してもらう。 |
| `ELM_EXPIRED` | 10 | 403 | 検証、クライアント、elm-server、elm-service | ライセンスやリースが、有効期限と猶予期間を過ぎている。サーバーでは、サーバーライセンスかライセンスの期限が切れている。 | ライセンスを更新するか、期限を延長する。 |
| `ELM_FEATURE_NOT_LICENSED` | 11 | 403 | 検証、elm-server、elm-service | 機能がライセンスに含まれていない。 | その機能を含むライセンスを求める。 |
| `ELM_FEATURE_VERSION_NOT_LICENSED` | 12 | 403 | 検証、elm-server、elm-service | 機能のバージョンが、ライセンスで許された範囲の外にある。 | このバージョンを含むライセンスを求める。 |
| `ELM_FEATURE_EXPIRED` | 13 | 403 | 検証、elm-server、elm-service | 機能が、その機能自体の有効期限を過ぎている。 | 機能の期限を更新する。 |
| `ELM_FINGERPRINT_UNAVAILABLE` | 14 | 400 | 検証、elm-server、elm-service | マシンフィンガープリントを計算できない。または、フィンガープリントが必要なリクエスト（トライアル、借用、フィンガープリントを照合するポリシーでのアクティベーション）にフィンガープリントがない。 | フィンガープリントを得られる環境で動かすか、ノードロックでないライセンスを使う。 |
| `ELM_INSTALLATION_KEY_UNREADABLE` | 15 | — | クライアント | インストール鍵を読めない、または作れない。 | 選んだスコープの鍵のフォルダーの権限を確かめる。 |
| `ELM_WRONG_KIND` | 16 | — | 検証、クライアント | ライセンスの種類が、求められた種類と違う。たとえば、トライアルをサーバーライセンスとして使った。 | 求められた種類のライセンスを使う。 |
| `ELM_KEY_REVOKED` | 17 | — | 検証 | ライセンスやリースが、トラストストアで失効した鍵で署名されている。 | 現在の鍵で署名したファイルを受け取る。 |
| `ELM_LEASE_OUT_OF_BOUNDS` | 18 | — | 検証 | リースがサーバーライセンスの範囲外にある。別のサーバーライセンスのリースである、サーバーライセンスにない機能やシート数を持つ、期間が長すぎる、サーバーライセンスの終了を過ぎている、のいずれかだ。 | サーバーライセンスを取得し直す。繰り返すなら、サーバーの管理者に伝える。 |
| `ELM_INVALID_STATE` | 19 | — | クライアント、elm、libelasticlm | 今はその呼び出しができない。サービスの URL がない、アクティベーションがすでに保存されている、アクティベーションが保存されていない、アクティベーション解除のプルーフがまだ保存されている、トークンの更新の時期ではない、別のプロセスがアクティベーションのロックを持っている、レスポンスのないリクエストが 16 回続いた、同じハンドルのコールバックの中から呼んだ、などだ。`elm` は、サーバーがライセンスをオンラインで更新しているときにこのコードを返す。 | メッセージに従い、先にアクティベーション解除をする、待つ、コールバックの外から呼ぶ、のいずれかをする。レスポンスのないリクエストが 16 回続いたあとは、もう一度アクティベーションする前に、管理者がそのインストールのアクティベーションを解除する。 |
| `ELM_PROOF_INVALID` | 20 | 401（オフラインのリクエストファイルでは 400） | 検証、elm-server、elm-service | リクエストのプルーフがない、検証に通らない、または別のメソッド、URI、本文、鍵のものである。オフラインのリクエストファイルの署名が検証に通らない。 | 同じインストールからリクエストを送り直す。オフラインのファイルなら、新しく作る。 |
| `ELM_NONCE_REQUIRED` | 21 | 401 | elm-server、elm-service | ノンスがない、または期限が切れている。レスポンスの `ELM-Nonce` に新しいノンスが入っている。 | 何もしない。クライアントが新しいノンスで再試行する。 |
| `ELM_REPLAYED` | 22 | 401（オフラインのリクエストファイルでは 409） | elm-server、elm-service | プルーフがすでに使われた。または、このリクエストのノンスを別のオフラインのリクエストが使った。 | 新しいリクエストかリクエストファイルを作る。 |
| `ELM_SERVER_PIN_MISMATCH` | 23 | — | 検証、クライアント | オンプレミスのサーバーが、クライアントがピンとして記録したサーバーではない。サーバーの鍵や TLS の鍵がサーバーライセンスの鍵と違う、または保存したピンが壊れている。 | クライアントが正しいサーバーにつながっているかを確かめる。意図してサーバーを置き換えたなら、ピンをリセットする。 |
| `ELM_PAYLOAD_TOO_LARGE` | 24 | 413 | elm-server、elm-service | リクエストの本文が 64 KiB より大きい。 | 本文を小さくして送る。 |
| `ELM_LICENSE_NOT_FOUND` | 30 | 404 | クライアント、elm-server、elm-service | ライセンスキーやライセンスが存在しない。クライアントは、アクティベーションが保存されていないときにこのコードを返す。`elm-server` は、サーバーライセンスのファイルがないと起動時に止まる。 | ライセンスキーや ID を確かめる。先にアクティベーションする。`elm-server` にライセンスファイルを渡す。 |
| `ELM_LICENSE_SUSPENDED` | 31 | 403 | elm-service | ライセンスが一時停止されている。 | ベンダーに問い合わせる。管理者がライセンスを再開できる。 |
| `ELM_LICENSE_REVOKED` | 32 | 403 | elm-service | ライセンスが失効している。 | ベンダーに新しいライセンスを求める。 |
| `ELM_ACTIVATION_LIMIT` | 33 | 409 | elm-service | ライセンスのアクティベーション数が上限に達した。 | ほかのデバイスのアクティベーションを解除するか、アクティベーション数を増やしてもらう。 |
| `ELM_DEACTIVATION_LIMIT` | 34 | 409 | elm-service | ライセンスのアクティベーション解除の回数が上限に達した。 | ベンダーに問い合わせる。管理者が代わりにアクティベーションを解除できる。 |
| `ELM_TRIAL_USED` | 35 | 409 | elm-service | このインストールのフィンガープリントで、この製品のトライアルがすでに使われている。 | ライセンスを購入する。管理者はトライアルの記録を削除できる。 |
| `ELM_CLONE_DETECTED` | 36 | 409 | クライアント、elm-server、elm-service | インストールのコピーが見つかった。`deny` の場合は、アクティベーションやリースが止まる。 | 管理者にアクティベーションを解除してもらい、もう一度アクティベーションする。止まったリースは、有効期限で終わる。 |
| `ELM_REQUEST_EXPIRED` | 37 | 400 | elm-service | オフラインのリクエストファイルの期限が切れている。 | 新しいリクエストファイルを作る。 |
| `ELM_REQUEST_MISMATCH` | 38 | — | クライアント | オフラインのレスポンスが、クライアントが待っているリクエストと一致しない。 | 最新のリクエストに対するレスポンスを取り込むか、新しいリクエストを作る。 |
| `ELM_TRIAL_NOT_OFFERED` | 39 | 404 | elm-service | 製品がトライアルを提供していない。 | ベンダーに問い合わせる。製品にトライアルのポリシーが必要だ。 |
| `ELM_NO_SEATS` | 40 | 409 | elm-server、elm-service | 機能に空いているシートがない。または、ライセンスで許されるシート数が、保持されているシート数より少なくなった。 | シートが空くのを待つか、シートを増やしてもらう。 |
| `ELM_UNKNOWN_LEASE` | 41 | 404 | elm-server、elm-service | サーバーがそのリースを知らない。 | `elm-server` から返ったなら、何もしない。サーバーの再起動のあと、クライアントがリースを再登録する。`elm-service` から返ったなら、リースは失われているので、新しいリースを取得する。管理者は、リース ID を確かめる。 |
| `ELM_BORROW_NOT_ALLOWED` | 42 | 403 | elm-server、elm-service | 借用が許されていない、または期間が上限を超えている。借用したリースは、リースの再登録の対象にならない。 | もっと短い期間で借用するか、借用を許可してもらう。 |

| `ELM_UNAUTHORIZED` | 50 | 401 | elm-server、elm-service | 管理者の認証に失敗した。管理者トークン、API キー、アクセストークン、セッションがない、または正しくない。 | トークン、API キー、サインインを確かめる。 |

| `ELM_RATE_LIMITED` | 52 | 429 | elm-server、elm-service | このアドレス、インストール鍵、API キー、管理者からのリクエストが多すぎる。レスポンスには `Retry-After` が付く。 | 待ってから、もう一度試す。 |
| `ELM_SERVER_BUSY` | 53 | 503 | elm-server | サーバーが今はこれ以上プルーフ ID を記録できない。 | しばらくしてから、もう一度試す。 |
| `ELM_NOT_FOUND` | 54 | 404 | elm-service | 管理 API の呼び出しが、存在しない対象を指している。たとえば、API キー、トライアル、利用ログのファイルだ。 | ID や名前を確かめる。 |
| `ELM_CONFLICT` | 55 | 409 | elm-service | リクエストが、対象の状態や一意の値と衝突する。使用中のコード、対象の状態では許されない変更、マシンに紐付けないライセンス以外のライセンスファイル、マシンに紐付けないライセンスのアクティベーション、クラウドのフローティングでないライセンスのリース、利用ログを書かないノード、などだ。 | メッセージに従う。マシンに紐付けないライセンスでは、アクティベーションせずにライセンスファイルを使う。 |

| `ELM_INTERNAL_ERROR` | 99 | 500 | すべての部分 | 内部エラー。データベースの処理が失敗した、ファイルに書き込めない、予期しない失敗が起きた、などだ。サーバーのレスポンスに未知のコードがあったときも、クライアントではこのコードになる。 | メッセージとサービスのログを読む。繰り返すなら報告する。 |
