# elm-server の設定

このページは、`elm-server` のすべての設定をまとめたものだ。`elm-server` は、顧客のネットワークでフローティングライセンスのシートを貸し出すオンプレミスのライセンスサーバーだ。サーバーをインストールして運用する人に向けている。サーバーの役割と、シート、リース、借用の仕組みは、先に[フローティングライセンス](../explanation/floating-licenses.md)を読むこと。

## コマンドラインと終了コード

```text
elm-server [--config <settings.json>] [--set-aside-broken-records]
```

| 引数 | 意味 |
| --- | --- |
| `--config <path>` | JSON の設定ファイル。指定しなければ、設定は環境変数だけから読む。[設定の渡し方](#設定の渡し方)を参照 |
| `--set-aside-broken-records` | 最新の借用の記録の検証に失敗しても起動する。壊れたファイルの名前を `borrows-broken-<UTC time>.jsonl` に変え、そのファイルにある借用を除いて起動する。除いた借用は数えないので、その借用が終わる前に、同じシートをもう一度貸し出すことがある。この引数がなければ、借用の記録が壊れているときは起動せず、終了コード 1 で終わる。借用の記録は[ログ](logs.md)で説明している |
| `--help`、`-h` | 使い方を表示し、0 で終わる |

これ以外の引数や、パスのない `--config` はエラーになる。

| 終了コード | 意味 |
| --- | --- |
| 0 | サーバーが正常に止まった（Ctrl+C、`SIGTERM`、またはサービスの停止）。または、`--help` で使い方を表示した |
| 1 | サーバーを起動できない。たとえば次のとき。サーバーライセンスがまだない（メッセージに、ベンダーに送るインストール鍵のサムプリントとマシンフィンガープリントを示す）。ルート公開鍵が指定されていない。設定で指定したファイル（ルート鍵、サーバーライセンス、TLS 証明書）を読めないか、有効でない。サーバーライセンスの検証に失敗した。`service.url` を設定しているのにサーバーライセンスを書き込めない。借用の記録が壊れているか、読み書きできない。利用ログを書き込めない |
| 2 | 不明な引数、パスのない `--config`、または設定のエラー。設定ファイルがない、読めない、64 KiB より大きい、または有効でない。値が有効でない。`product` がない |

終了コード 1 か 2 で終わる前に、`elm-server` は `error:` と理由を表示する。

## 設定の渡し方

- 設定は、JSON の設定ファイル、環境変数、またはその両方で渡す。ファイルは `--config` で渡す。

  ```text
  elm-server --config /etc/elm-server/settings.json
  ```

- `--config` がなければ、`elm-server` は環境変数だけを読む。
- 環境変数は、ファイルにある同じ設定より優先する。空の値を設定した環境変数は、設定されていないものとして扱う。
- ファイルは 64 KiB までだ。ファイルが知らないキー（たとえばつづりを間違えたキー）はエラーになる。キーの名前は大文字と小文字を区別する。
- 設定にエラーがあると、`elm-server` は起動する前に止まり、`error:` と理由を表示する。終了コードは[コマンドラインと終了コード](#コマンドラインと終了コード)にある。

### 環境変数の名前

環境変数の名前は、`ELM_` のあとに設定のパスを大文字にして続け、`.` を `_` に置き換えたものだ。たとえば、`rateLimit.perIp` は `ELM_RATELIMIT_PERIP`、`publicUrls` は `ELM_PUBLICURLS` になる。リストは 1 つの値として書き、要素を `;` で区切る。たとえば `ELM_ALLOW=10.0.0.0/8;192.168.1.0/24` だ。

次の 2 つの環境変数は、この規則に従わない。

| 環境変数 | 中身 |
| --- | --- |
| `ELM_TRUST_ROOT_KEYS` | ベンダーのルート公開鍵の PEM テキスト。ファイルのパスではない。`trust.rootKeys`（ファイルの中、または `ELM_TRUST_ROOTKEYS`）がファイルを 1 つも指定していないときだけ読む |
| `ELM_TLS_PASSWORD` | `tls.certificate` で指定した PKCS#12 ファイルのパスワード。設定ファイルには対応する設定がない |

## 最上位の設定

| 設定 | 環境変数 | 型 | 既定 | 範囲と注意 |
| --- | --- | --- | --- | --- |
| `product` | `ELM_PRODUCT` | 文字列 | なし（必須） | サーバーライセンスの製品 ID。英小文字、数字、`-` からなる 1 から 64 文字。既定の `dataDirectory` の名前にも使う |
| `listen` | `ELM_LISTEN` | URL | `https://0.0.0.0:7070` | サーバーがクライアントを待ち受ける場所。クエリとフラグメントのない `https` の URL。ホストは IP アドレス、`localhost`、`0.0.0.0`、`[::]` のいずれか |
| `publicUrls` | `ELM_PUBLICURLS` | URL のリスト | `listen` から作る | クライアントがサーバーに接続するときの URL。クライアントのプルーフは、このうちの 1 つを指定していなければならない。どれもクエリとフラグメントのない `https` の URL。省略したときは、`listen` のホストが `0.0.0.0` か `[::]` なら `https://<host name>:<port>/` と `https://localhost:<port>/`、それ以外なら `listen` の URL になる |
| `license` | `ELM_LICENSE` | ファイルのパス | `elm-server` の実行ファイルと同じフォルダーの `server.elmlic` | サーバーライセンスのファイル。`service.url` を設定したときは、サーバーがこのファイルに書き込めなければならない |
| `allow` | `ELM_ALLOW` | 文字列のリスト | なし | リースのリクエストを許可するエントリー。[アクセスルール](#アクセスルール)を参照 |
| `deny` | `ELM_DENY` | 文字列のリスト | なし | リースのリクエストを拒否するエントリー。[アクセスルール](#アクセスルール)を参照 |
| `dataDirectory` | `ELM_DATADIRECTORY` | フォルダーのパス | Windows では `%ProgramData%\ElasticLM\<product>`、macOS では `/Library/Application Support/ElasticLM/<product>`、Linux では `/var/lib/elasticlm/<product>` | サーバーのインストール鍵、時刻の状態、借用の記録、管理者トークン、（既定では）利用ログを置くフォルダー。同じ製品のアプリが同じマシンで動くときは、サーバー専用のフォルダーを指定する |

### アクセスルール

`allow` と `deny` のエントリーは、次のいずれかだ。

| エントリー | 一致するもの |
| --- | --- |
| IP アドレス（`192.168.1.20` など） | そのアドレス |
| CIDR の範囲（`10.0.0.0/8` など） | 範囲内のすべてのアドレス |
| `host:<name>` | クライアントが送るホスト名。大文字と小文字を区別しない |
| `user:<name>` | クライアントが送る OS のユーザー名。大文字と小文字を区別する |

- `allow` と `deny` のエントリーは、合わせて 1,000 個までだ。`host:` と `user:` の名前は 1 から 255 文字。
- IP のエントリーは、すべてのリースのリクエストに適用する。`host:` と `user:` のエントリーは新しいリースにだけ適用する。クライアントがホスト名とユーザー名を送るのは、送るように設定したとき（`ClientInfoStrategy: HostAndUser`）だけだ。これらの名前はクライアントが自分で名乗るもので、サーバーは確かめられない。
- 種類（IP、ホスト、ユーザー）ごとに、`deny` のエントリーに一致するか、その種類の `allow` のエントリーがあってどれにも一致しないとき、リクエストを拒否する。ホスト名やユーザー名のない新しいリースは、`host:` と `user:` のどのエントリーにも一致しない。
- 拒否したリクエストには、`403` と `ELM_FORBIDDEN` を返す。

## `rateLimit`

| 設定 | 環境変数 | 型 | 既定 | 範囲と注意 |
| --- | --- | --- | --- | --- |
| `rateLimit.perIp` | `ELM_RATELIMIT_PERIP` | 整数 | `20` | 1 つの送信元（IPv4 アドレス、または IPv6 の /64）からの 1 秒あたりのリクエスト数。1 から 10000。上限を超えたリクエストには `429` と `ELM_RATE_LIMITED` を返す。`elm-server` は `X-Forwarded-For` を読まないので、リバースプロキシや NAT の内側にあるクライアントは、すべて 1 つの送信元として数える |

## `trust`

| 設定 | 環境変数 | 型 | 既定 | 範囲と注意 |
| --- | --- | --- | --- | --- |
| `trust.rootKeys` | `ELM_TRUST_ROOTKEYS` | ファイルのパスのリスト | なし（必須） | ベンダーのルート公開鍵の PEM ファイル。サーバーライセンスの鍵証明書を、この鍵で確かめる。ファイルの代わりに、`ELM_TRUST_ROOT_KEYS` に PEM テキストを入れてもよい。どちらもなければ、サーバーは起動しない |
| `trust.revokedKeyIds` | `ELM_TRUST_REVOKEDKEYIDS` | 文字列のリスト | なし | サーバーがもう信頼しない鍵 ID（`kid`） |

## `tls`

| 設定 | 環境変数 | 型 | 既定 | 範囲と注意 |
| --- | --- | --- | --- | --- |
| `tls.certificate` | `ELM_TLS_CERTIFICATE` | ファイルのパス | なし。サーバーが起動のたびに、インストール鍵で自己署名証明書を作る | サーバーの TLS 証明書。`tls.key` を設定したときは PEM の証明書、設定しないときは PKCS#12 ファイルで、そのパスワードは `ELM_TLS_PASSWORD` に入れる。証明書には秘密鍵が含まれていなければならない |
| `tls.key` | `ELM_TLS_KEY` | ファイルのパス | なし | PEM の `tls.certificate` に対応する PEM の秘密鍵 |

## `borrow`

| 設定 | 環境変数 | 型 | 既定 | 範囲と注意 |
| --- | --- | --- | --- | --- |
| `borrow.maxDuration` | `ELM_BORROW_MAXDURATION` | 期間 | ライセンスにある上限 | このサーバーが許す借用の最長期間。書式は `d.hh:mm:ss` で、たとえば `7.00:00:00`。1 秒から 100 年まで |
| `borrow.reserve` | `ELM_BORROW_RESERVE` | 整数 | `0` | 機能ごとに、借用に回さずに残しておくシートの数。0 から 1000000 |

## `log`

| 設定 | 環境変数 | 型 | 既定 | 範囲と注意 |
| --- | --- | --- | --- | --- |
| `log.usage` | `ELM_LOG_USAGE` | ファイルのパス | `usage.jsonl` | 利用ログ。日ごとのファイルの名前は、このパスのフォルダーと拡張子を除いたファイル名から決まる（既定では `usage-<UTC date and time>.jsonl`）。相対パスは `dataDirectory` の下とみなす。ファイルを指していなければならない |

## `admin`

| 設定 | 環境変数 | 型 | 既定 | 範囲と注意 |
| --- | --- | --- | --- | --- |
| `admin.listen` | `ELM_ADMIN_LISTEN` | URL | `http://127.0.0.1:7071` | ローカルの管理 API が待ち受ける場所。ループバックアドレス（または `localhost`）の `http` の URL で、パスとクエリを含まない |

## `service`

| 設定 | 環境変数 | 型 | 既定 | 範囲と注意 |
| --- | --- | --- | --- | --- |
| `service.url` | `ELM_SERVICE_URL` | URL | なし。サーバーライセンスのトークンの更新を自動では行わない | サーバーライセンスのトークンの更新をする `elm-service`。`https` の URL、またはループバックアドレスの `http` の URL。設定したときは、サーバーは起動時に `license` のファイルに書き込めるかを確かめる |

## 例

```json
{
  "product": "acme-cad",
  "listen": "https://0.0.0.0:7070",
  "publicUrls": ["https://licenses.example.com:7070/"],
  "license": "/etc/elm-server/server.elmlic",
  "trust": {
    "rootKeys": ["/etc/elm-server/acme-root.pem"]
  },
  "allow": ["10.0.0.0/8"],
  "rateLimit": {
    "perIp": 50
  },
  "borrow": {
    "maxDuration": "7.00:00:00",
    "reserve": 2
  }
}
```
