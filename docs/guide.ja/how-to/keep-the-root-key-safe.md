# ルート鍵を安全に保管する

このガイドは、ルート鍵を持つベンダーに向けている。ルート鍵は、すべての署名鍵を証明する鍵だ。ルート鍵のファイルとそのパスフレーズを手にした人は誰でも、自分の署名鍵を証明して、そのルート鍵を信頼するすべてのアプリが受け入れるライセンスを作れる。また、ファイルのコピーが 2 つとも失われるか、パスフレーズが失われると、新しい署名鍵を証明できなくなる。どちらの場合も、元に戻すにはアプリの更新が要る。このガイドでは、ルート鍵をどこに置くか、コピーをどう持つか、コピーがまだ使えるかをどう確かめるかを説明する。ルート鍵 `root.key.pem`、その公開鍵 `root.pub.pem`、ルート鍵が証明した署名鍵の公開鍵 `signing.pub.pem` がある状態から始める。[ライセンスを発行して .NET のアプリで確かめる](../tutorials/verify-a-license-offline.md)で、これらを作れる。ルート鍵の役目は[ルート鍵](../explanation/trust-chain.md#ルート鍵)で説明している。

<!-- steps:after page=docs/guide/tutorials/verify-a-license-offline.md -->

## 始める前に

コマンドは、チュートリアルのフォルダーで、その `tools` フォルダーを `PATH` に足した状態で打つ。ファイル名は自分のものに置き換える。

下の出力にある鍵 ID と日時は架空の値だ。手元のマシンでは違う値になる。

## ルート鍵の ID を控える

鍵 ID は、公開鍵から計算する短い名前だ。どの鍵証明書も、自分を証明したルート鍵をこの ID で示す。そのため、`root.key.pem` のコピーにどのルート鍵が入っているかを、この ID で見分けられる。鍵 ID を表示する。

<!-- steps:run -->
```shell
elm key thumbprint root.pub.pem
```

`elm` は鍵 ID を表示する。

```text
FAKE-ROOT-KEY-ID-000000000000000000000000R1
```

ルート鍵のコピーを記録している場所に、これを書き留めておく。公開鍵とその ID は秘密ではない。どのアプリも、トラストストアに公開鍵を持っている。

## 鍵をオフラインに置く

- `root.key.pem` は、ネットワークにつながっていないマシンか、USB ドライブのようなリムーバブルメディアに置く。メディアは、鍵を使うときだけつなぐ。`elm-service` を動かすマシン、リポジトリ、コンテナイメージ、サーバーのバックアップには決して置かない。
- 使うのは `elm key certify` だけにする。[署名鍵を入れ替える](rotate-the-signing-key.md)のように新しい署名鍵を証明するときと、署名鍵の鍵証明書を更新するときだ。ほかのコマンドも、ElasticLM のほかのプログラムも、ルート鍵を読まない。
- ルート鍵には、どの署名鍵にも使わない専用のパスフレーズを付ける。たとえばサービスを動かすマシンから署名鍵のパスフレーズを知った人に、ルート鍵のパスフレーズまで知られないようにするためだ。チュートリアルですべての鍵に同じパスフレーズを使ったのは、手順を短くするためだけだ。`elm` は鍵ファイルのパスフレーズを変えられないので、製品のルート鍵は、最初から専用のパスフレーズを付けて、オフラインのマシンで `elm key root create` で作る。
- `elm` は鍵をパスフレーズで暗号化したまま保存し、鍵を使うたびにパスフレーズを尋ねる。パスフレーズは、`elm` が尋ねたときに打つ。スクリプトには書かず、ファイルやターミナルのプロファイルで `ELM_KEY_PASSPHRASE` に入れておくこともしない。パスフレーズは鍵ファイルとは別に保管し、片方を見つけた人がもう片方まで手にすることがないようにする。

## コピーを 2 つ持つ

`root.key.pem` を、PowerShell の `Copy-Item` や Bash の `cp` のようなシステムのツールで 2 つのリムーバブルメディアにコピーし、火事や盗難で両方を失わないよう、別々の場所に保管する。どのコピーも元のファイルと同じく秘密で、同じパスフレーズで暗号化されている。パスフレーズも、あとで見つけられるように保管する。パスフレーズのないコピーは、コピーがないのと同じだ。

鍵のコピーがすべて失われるか、そのパスフレーズが失われると、新しい署名鍵を証明できなくなり、署名鍵の鍵証明書はそれぞれの有効期間のうちに切れていく。元に戻す方法は新しいルート鍵だけで、それにはアプリの更新が要る。手順の順番は[ルート鍵を入れ替える](../explanation/trust-chain.md#ルート鍵を入れ替える)にある。コピーがパスフレーズと一緒に盗まれたおそれがあるときは、[ルート鍵が漏れたとき](../explanation/trust-chain.md#ルート鍵が漏れたとき)を読む。

## コピーが使えるかを確かめる

コピーを作ったあとと、その後もときどき、コピーがまだパスフレーズで読めるかを確かめる。確かめるには、コピーで署名鍵の公開鍵を証明する。まず、ターミナルから `ELM_KEY_PASSPHRASE` を消す。こうすると `elm` がパスフレーズを尋ねるので、パスフレーズをまだ覚えていることも確かめられる。PowerShell では `Remove-Item Env:ELM_KEY_PASSPHRASE` と打ち、Bash か zsh では `unset ELM_KEY_PASSPHRASE` と打つ。`--root` には、`root.key.pem` の代わりにコピーのパスを渡す。`elm` は `--force` なしでは既存のファイルを上書きしないので、`--out check.cert` には新しいファイルを指定する。`--days 1` で、鍵証明書の有効期間を短くする。

<!-- steps:run -->
```shell
elm key certify --root root.key.pem --public signing.pub.pem --out check.cert --days 1
```

`elm` はパスフレーズを尋ね、鍵証明書を表示する。

```text
Passphrase for 'root.key.pem':
certificate: check.cert
signing key ID: FAKE-SIGNING-KEY-ID-000000000000000000000S1
root key ID: FAKE-ROOT-KEY-ID-000000000000000000000000R1
uses: license
valid: 2026-01-15 09:30:00Z to 2026-01-16 09:30:00Z
```

<!-- steps:expect -->
```text
certificate: check.cert
uses: license
```

`root key ID:` を、控えておいた鍵 ID と比べる。同じなら、そのコピーはルート鍵で、パスフレーズも正しい。`elm` は、ルート鍵とほかの秘密鍵を区別できない。署名鍵のファイルを渡すと、その鍵で証明し、`root key ID:` にはその鍵の ID が出る。

そのあと `check.cert` を削除する。署名鍵にはすでに自分の鍵証明書があるので、このファイルはどこにも使わない。

2 つのコピーがこの確認に通ったら、鍵を作ったマシンのように、ネットワークにつながるすべてのマシンから `root.key.pem` を削除する。それ以降、鍵はオフラインのマシンかリムーバブルメディアにだけある。

| `elm` の表示 | 起きたこと | 対処 |
| --- | --- | --- |
| `error: The key 'root.key.pem' is not an encrypted P-256 private key, or the passphrase is wrong.` | パスフレーズが違うか、ファイルが `root.pub.pem` のような秘密鍵でないファイルだ。 | パスフレーズをもう一度打つ。それでも失敗するなら、コピーが壊れている。もう一方のコピーを使い、そこから新しいコピーを作る。 |
| `error: The file 'root.key.pem' does not exist.` | パスがコピーを指していない。 | コピーのパスと、そのメディアがつながっているかを確かめる。 |
| `error: The file 'check.cert' exists. Pass --force to overwrite it.` | 前の確認で作ったファイルが残っている。 | そのファイルを削除し、もう一度証明する。 |

どの場合も、`elm` は終了コード 2 で終わる。終了コードは[elm コマンドリファレンス](../reference/elm-cli.md#終了コード)に挙げている。
